# Windows 无缝播放 0.4.34

当前版本 **0.4.34**，已在网易云 x64 **3.1.44.205670** ＋ BetterNCM **1.3.4** 验证加载（包含 0.4.33 共用 Range 有界接收保护）。插件入口允许随客户端加载，音频接管需要现有原生桥及打包时核对的选曲模块匹配。网易云升级后若模块有变化，菜单显示原生播放状态。打包使用当前客户端归档。

隔离检查覆盖队列重建、改动后续曲目、实际下一首变化、重复队列项，以及缓存读取失败时原始 Load 的回退。实机验收范围和包哈希见[当前状态](../docs/CURRENT_STATUS.md)和[统一版本记录](../docs/versions.json)。

## 插件入口

右上角统一 BetterNCM 菜单，显示无缝开关、状态和「管理插件」；打开管理页后该项变为「返回网易云」。复用宿主管理页并默认打开无缝配置，不添加第二套市场。样式限定在自己的弹层及已打开的宿主管理页，不注入歌词页。Ctrl+Alt+G 使用同一入口。

0.4.11／0.4.12 修改入口与管理界面，音频链路沿用 0.4.10。本机上游移除未使用的 LibEAPIRequest 后报告市场在线列表可加载，保留 NativeWindowControls；这不是其他电脑的依赖卸载指令，也不能保证市场网络状态。Mac 只对齐已安装管理和样式，没有启用 Windows 通用市场。[两端菜单范围](../docs/PLUGIN_MENU_ALIGNMENT_0.3.8_0.4.12.md)。

0.4.18 修正随机播放能力检测：检查实际网易云选曲函数，而非不包含该能力标记的预加载包装函数。随机模式及「下一首播放」继续复用宿主 randomOrder，不另建随机队列。实际客户端选曲函数的插队、随机回绕和能力降级通过隔离检查；已安装并重启，文件一致，未做本版实际听测。

0.4.19 只补充诊断：最多保留 16 条回退／原生加载关键记录，独立于最近 80 条普通事件，并记录当前 Web 所有权、随机能力和下一首可确定状态。字段白名单继续排除音源 URL 和凭证。已验证高频日志轮转后仍保留原因；不修改播放算法，尚不能据此断言用户本次回退已修复。

0.4.20 修正自然跨曲后未保留上一首暖缓冲；和手动切歌共用最近一首的有界保留，仍在内存预算内。磁盘缓存 MD5 保留逐块校验，以约 4 ms 工作预算和 MessageChannel 让出执行，避免每 64 KB 等待嵌套计时器造成几秒起播延迟。此前 0.4.19 实际日志两次本地缓存资源准备约 3571／3575 ms，立即内存切回约 2 ms；修正通过暖缓冲保留／替换／释放及 MD5 正确、损坏、取消、代次检查。已安装重启，未做本版界面切回听测。

0.4.21 支持心动模式。使用网易云已经排好的下一首，按实际宿主选曲函数预约。推荐尚未补到队尾时等待队列更新。隔离检查覆盖推荐替换、尾部追加及重复项。

0.4.23 提前准备索引 FLAC 后续区间，按 PCM 容量限制预读长度。普通播放推进会保留已发出的补缓冲请求，手动拖动、切歌仍能取消过时的读取。持续的读取或输出故障由网易云原生恢复。

0.4.25 针对切歌、拖动延迟和流式稳定性做专项修复：本地挂载读取优先 `127.0.0.1`（失败自动回退原 URL），合并区间读取上限至 2 MiB 并使用 32 位 XOR；复用空闲 `FLACDecoder` 实例、延迟非索引解码器创建并预取首段缺失区间；磁盘已覆盖目标改为 0.5 秒起播跑道并由区间进度事件直接唤醒，消除首次加载差 3 ms 触发二次解码与 30 ms 轮询；`loadOwned` 并行执行音频上下文初始化、门控与缓冲准备；缩短流式排程前置量至 20 ms、扩大安全排程窗口至最高 10 秒（受 6 MiB 字节预算约束）并按 2 秒块排程；扩大暖缓存 LRU 至最多 4 首（≤160 MiB）、延长空闲上下文保活至 15 秒，并修复瞬态 `cancelled` 污染流错误及 `output-clock-timeout` 过紧问题。

0.4.26 修复拖动/点击进度条等待区间解码期间，40 ms 心跳仍推送旧播放位置导致进度条短暂回跳（左移一下再弹回）的问题：`pendingStreamSeek` 或 `seekReplies` 未完成时暂停推送旧进度，待 `onSeek` 确认后立即以目标位置同步进度。

0.4.27 为流式音频节点增加 `node.onended` 续喂触发，降低后台定时器节流引发断流的风险；允许在关闭再开启无缝开关时重置空闲缓存会话的 `fault` 锁，避免偶发停止异常后必须重启客户端。

0.4.29 移除自定义进度条流光样式，仅保留无缓存切歌即时 `PlayProgress(0, cache=0)` 归零，加载提示完全沿用网易云原生圆点动画；修复 0.4.28 首轮 250 ms 拉数过短及停止后仅等 50 ms 导致远程新歌反复打断重下的回退——改为 `600 / 1200 / 2000 / 3000 ms` 渐进窗口、停止后在 `50 / 110 / 190 ms` 复核索引提交；`snapshotSource` 优先使用原生同步 `betterncm_native.fs.exists` 消除约 300 ms 探测延迟；待当前曲缓冲 ≥10 秒后再预加载下一首，避免抢占冷启动带宽。

0.4.30 全量复核修复：暂停态恢复允许下一首预加载、播放态缓冲门槛下调至 6 秒以兼容 192 kHz Hi-Res；修复远期预约曲目 `stream.done` 后被 `farFuture` 跳过全量排程的问题；将 4 轮冷下载拉数窗口调整为 `600 / 1200 / 2000 / 2500 ms` 并按 8 秒截止前 400 ms 动态封顶确保 `Stop` 正常提交 `.idx`；为 `PlaybackClock.open()` 增加 `openSerial` 取消代次并在 `loadOwned` 异常路径清理兄弟缓冲任务；为同步 `fileExists` 与 Webpack 模块扫描增加 `try/catch` 容错。

0.4.31 依据 `0.4.30` 实机日志调优远程冷加载：将高优切歌/拖动的首轮拉数窗口提升至 `1200 / 1800 / 2500 ms`（后台补缓冲 `1800 / 2400 / 2800 ms`，继续受 8 秒截止前 400 ms 约束），避免 `600 ms` 过短反复打断重下；限制远期已预约下一首仅预读 4 秒（低水位 3 秒），防止抢占当前曲拖动通道导致 8 秒超时重来。

0.4.32 恢复网易云原生 3 秒进度圆点加载闪烁（移除 0.4.31 的 250 ms 提前显影覆盖）；修复点击进度条时偶发“先左跳回旧位置、再右跳到目标位置”的竞态——网易云进度条在 `pointerup` 时立即清除拖拽标记，而 `setPlayingPosition` 经异步 Redux-Saga 发出 `audioplayer.seek` 存在 10–30 ms 间隙，导致 50 ms 进度心跳推送旧位置；现通过捕获进度条指针交互并在松手后提供 250 ms（或在 `audioplayer.seek` 到达时立即移交）的静音保护窗口消除该回跳。

0.4.33（源码）恢复共用 Range 接收过程的 2 MiB 有界流式读取保护。

0.4.34 修复长时运行或复播部分缓存曲目时曲中 `native-only-cache-range-timeout` 回退原生的两处根因：① `NativeByteSource` 增加 `updateSource()`，在 `loadOwned` / `claim` / `prepare` 收到网易云最新授权音源时同步刷新闭包内的 `musicurl`，避免复用超过有效期的旧签名 URL（并同步 Mac 0.3.20 的 `remaining < 250` 提前超时判断）；② `GaplessCacheCoverage.seekIntoGap()` 在 `seekBefore()` 落入已缓存边界且连续零进展时自动微调至缺口字节之后，强制触发原生拉数；③ 后台 `ensure()` 在仍有 ≥2 秒可播跑道时允许 1 次瞬态超时重试，不再在 5.8 秒余量时直接断流回退。

## 打包安装

```powershell
python windows/package.py --client "C:\Program Files\NetEase\CloudMusic\package\orpheus.ntpk"
```

产物为 `dist/gapless-player-windows-0.4.34.plugin`。打包使用对应客户端归档。同 slug 活动目录只保留一个版本；旧包备份到目录之外，重启后核对 manifest、main、startup 及运行诊断版本。打包生成 ZIP 插件并内置 FLAC 解码库。

默认原生数据源，`--native-source-trial` 为兼容别名；显式 `--web-source` 生成旧路径包，新歌不保证原生持久缓存。无需 LibEAPIRequest 作为本无缝插件依赖；其他插件依赖应按各自说明处理。

## 播放与边界

网易云提供授权音源、档位、队列和原生缓存；插件只读有效区间，缺口由原生 Load／Seek／Stop 串行准备，Web Audio 连续输出。明文本地 FLAC、索引 Seek、当前及切走歌曲的有界后台补齐保留既有实现。编码区块共享 64 MiB，索引路径单曲 PCM 32 MiB；未索引路径受 512 MiB 管理预算约束。

同率可提前预约；位深／声道差异不再阻断预取，异率保留资源并在下一次 Load 重建输出，可能有短间隔。手动选曲没有人为等待定时，但客户端 Stop → Load、授权、缓存和输出准备仍会耗时。无缝优先，关闭后原生沿用保存的音效偏好；重新开启在下一次有效 Load 接管，保留当前原生播放。

不保证播放／跳到曲尾后整首必定提交，也不以第二套永久缓存替代。SMTC 既有实测没有时间线／Seek，物理媒体键及极端网络／设备场景仍有验收边界。Windows 没有新增原生/Web 输出 A/B；Mac 结果不能替代 Windows 设备结果。
