# 0.1.8 系统控制与音源交接修正

目标不变：只增加无缝衔接，保留网易云的授权音源、音质选择、音量、队列和窗口样式。本轮未改解码、缓存规格、音量增益或采样率；没有新增 CSS、DSP、混音或静音裁剪。

## 确认的接入缺陷

1. 0.1.7 的 Media Session 播放／暂停／前后切歌处理只记录事件，依赖原生处理；跨曲后原生引擎仍停在上一首，不能作为当前音乐的控制所有者。系统 Seek 还经过 SDK 的全局完成订阅，增加了不必要的依赖。
2. 系统会话在原生 pause 完成后才建立，存在系统先显示暂停、再显示播放的窗口。
3. 实机完成无缝跨曲并操作上一首／下一首后，回退到原生播放的控制中心明确显示上一首、下一首、进度滑块为 disabled。释放 Chromium 系统会话会禁用共享的 macOS 远程命令，而网易云没有在普通 Load 后重新启用它们。这是插件接入的副作用，不能归为正常现象。

## 修正

- 在原生仍播放时准备系统会话并等待载体 play 完成，再执行音乐后端交接。交接暂停握手不改变逻辑上的用户播放意图。
- 复用同一个系统会话，跨预约边界、普通选曲和原生回退保留；音乐所有者与系统会话生命周期分开。
- Web Audio 的系统 Seek 直接调用与窗口 Seek 相同的时钟调整函数，不通过 SDK 的全局完成订阅；窗口自身的 SDK RPC／通知保持原协议。
- 系统前后切歌复用网易云 `playingList/jump2Track`，指定当前曲目，沿用原队列策略。播放／暂停使用明确意图，避免把两个通知都当作切换。
- 启动桥额外识别原有 `winhelper.onHotkey` 通知。原生与 Chromium 的同一系统操作可能同时到达，80 ms 内合并同类重复通知，避免一次暂停又恢复或一次切两首。其他快捷键保持原路径。
- 原生回退时同步其进度和状态；系统 Seek 保留原生远程命令处理，不向原生额外发送一次 Seek。只有 Web Audio 拥有音乐时才由插件 Seek 时钟。

## 生命周期边界

系统载体不输出音乐，只用于发布系统媒体状态。已经建立的会话在关闭无缝后继续镜像原生，直到页面退出；关闭核心仍清空下载、解码资源并恢复原生音乐输出。立即拆掉会话会再次禁用系统控件，因此没有这样处理。

首次建立仍要求可用的音频上下文和系统会话。刷新页面时不在恢复事务的占位实例上提前建立会话，避免没有真实输入时触发 autoplay 拒绝。页面销毁、系统会话异常时清理载体；异常不关闭无缝核心。应用重启／页面销毁后的系统控件重新注册仍需额外覆盖，不能把当前会话的验证外推到所有系统生命周期。

## 实机验证与限制

- 最终 0.1.8 源码已实际完成 Baptized In Fear（2670863319）→ Open Hearts（2670863152）预约衔接，接认约 149 ms；两首音频没有因接认重新开始。
- 本轮系统控制路由已通过真实控制中心操作：跨曲后的 Seek 到约 27.107 s 和 59.950 s 都作用于 Open Hearts，随后暂停、继续、上一首及下一首各执行一次，队列 ID 与实际播放状态一致。重复的原生／Chromium 播放通知没有导致再次切换。
- 最终源码还完成 Open Hearts → Moth To A Flame（1938192798）的原生回退：下一首因资源限制走原生，系统会话仍 active，音乐节点数为 0，系统元数据和播放状态跟随原生。这个边界不承诺无缝。
- 控制中心在播放时显示暂停按钮，网易云窗口样式保持原样。用户再次确认上一首／下一首正常，但图标仍短暂切换，进度仍有新→旧→新的回跳。暂停时 10 帧、播放中操作返回后 35 帧的采样没有覆盖操作最初瞬间，不能推翻用户反馈。
- 原生对照也存在的进度回跳、音频设备切换、长时间休眠与声卡连续性没有新增验收结论。

没有新增测试用例，没有执行全量 lint／TypeScript 检查或应用构建；执行变更 JS 的语法检查、现有客户端协议与控制中心操作、源码和安装 ZIP 一致性核对。

## 仍未解决：系统状态有两个发布者

附加探针确认：实际 Web Audio 曲目为 Open Hearts（2670863152），播放中系统 Seek 后原生仍发出 Baptized In Fear（2670863319）的 onPlayProgress，位置约 157.83 s；实际音乐约 158.423 s 且 Media Session 始终报告 playing。暂停 Seek 也收到旧曲目约 172.78 s 的原生进度。探针已移除，并恢复对照前的暂停和约 196.273 s 位置。

页面桥已经拦住旧原生回调，不能拦住原生 `seekWithEvent:` 直接调用 `setCurrentTime:`，或 TouchBar/NowPlaying 管理器直接写 MPNowPlayingInfoCenter。原生后端被停住后，其位置／暂停状态与当前 Web Audio 不同；原生写入与 Chromium 发布的真实时钟竞争，是目前图标闪动和旧位置覆盖最符合证据的原因。纯原生对照也有进度回跳，因此不能把所有回跳归为插件引入。

没有继续添加反复 Seek、周期强制播放／暂停、第二条音乐流或修改用户音量。这些方法不能建立唯一状态所有者，还会增加音频副作用。彻底治理需要在原生层协调系统命令和 NowPlaying 状态的所有权，接管期间阻止停住的原生后端发布状态，原生恢复后再交还。当前 BetterNCM 的 JS 接口没有已验证的拦截路径；本轮没有修改网易云二进制、注入原生钩子或把原生桥方案宣称为已实现。

0.1.8 是控件恢复的修正版本，不是所有系统面板问题都解决的版本。
