# 曲尾流式解码误降级：Mac 0.3.11 / Windows 源码 0.4.15

本轮抓到实际回退：曲目 22676181 在 220.087 秒、距曲尾约 24.42 秒时，输出报告 `stream-integrity`，随后恢复原生；下一首 22676164 的无缝预约随恢复取消。这与无关歌单更新的 0.3.10 修正是两个问题。

## 复现与原因

读取同一首歌的原生已提交缓存进行独立解码：225.9998–227.9967 秒的 FLAC 索引区间应包含 88064 帧，旧 `decodeFile` 只返回 87040 帧。前后拼接解码返回完整数据，表明存在分块终止位置的解析问题，不能把短结果直接当成该音源不可播。当前输出提前准备约 8 秒的数据，故该段错误可以在约 220 秒就触发回退。

内置 0.2.11 包的解析器需要下一帧头来确定当前帧结束。单独分块被作为文件 EOF 提交时，部分有效末帧会被漏掉。旧代码又把具体异常折叠为 `indexed-read-failed` / `stream-integrity`，不能只看最后的通用原因定位问题。同一次历史回退的底层异常未被保留；本轮独立复现的位置与它一致，但不能排除其他读取故障。

## 修正

- 非文件末尾的索引区间额外读取至多 16 字节，校验当前和下一帧头的 CRC8、帧号及索引采样位置；使用流式 `decode`，不把下一帧的有限前瞻强制作为 EOF flush。真正文件末尾仍用 `decodeFile`。
- 仍要求结果采样数、采样率、位深、声道完全匹配；不补静音、不截短缺失 PCM、不放宽缓存有效区间或源身份。编码读取、PCM 和原有临时缓存预算继续有界。
- 检查内置压缩解码包实际返回的 `U` 错误数组，同时兼容未压缩包的 `errors`。保留最近一次区间失败的具体原因、曲目和目标位置；新页面的 Mac `lastFallback.streamError` 同时保存底层原因。
- 音源、采样率策略、音量、歌词、频谱、队列与声音预约时钟不变。

同一原生缓存的 123 个索引区间全部通过修正后的读取和解码。原问题段与两个相邻区间连续解码的对应 PCM 逐采样比较，最大差值为 0。检查源码与包内 JS 语法，安装包和宿主准备的运行文件一致；没有新增测试用例、全量静态检查、应用构建或声音回录。[数值记录](verification/mac-indexed-decoder-0.3.11.json)。
