# 原生数据源普通启动与开关检查

2026-11-15，Windows 网易云 3.1.43.205627，候选源码 `3be14d6`。通过正常退出、更换单一同 slug 包、正常启动验证，没有启用调试端口。安装包与打包产物 SHA-256 一致。

## 实际观察

- 从“我喜欢的音乐”播放 Baptized In Fear，日志 Web 装载 941 ms（并非端到端首声），下一首 Open Hearts 提前完成准备。
- 点击进度条至 225.04 秒，目标缓冲准备 565 ms，随后出现 boundary 和 claimed，接认 227.6 ms。没有观察到此次边界的 stream-output-fallback 或 claim-timeout。这次回录期间出现其他视频播放和额外手动 Seek，不作为独立声音验收。
- 用户暂停其他声音后，重新选曲，再跳至 225.04 秒，已有内存缓冲下准备 81 ms，随后 boundary 与 claimed，接认 358.3 ms。30 秒回录无采集错误，但录音末尾早于该 boundary，无法证明完整声音边界连续。关联分析必须先确认边界位于采集区间，不能将越界时间插值到最后一个采样后得出的相关性解释为音频间隙。
- 右上角插件菜单可以打开，只有无缝播放开关；关闭按钮仍独立位于标题栏右端。关闭无缝时记录 restore → restored，相同位置 12.8348 秒，耗时约 281 ms，菜单明确显示原生播放。
- 重新开启后，当前原生歌曲仍继续播放，但旧 prepare 流程尝试请求没有所有权的数据源，记录 native-only-cache-provider。重新选歌则能正常进入 Web 播放。

## 针对开关的修正

原生取数通道会复用宿主后端，因此不能在该后端正在发声时运行辅助 Load/Seek。此次阻止试验模式在尚未拥有输出时进入 prepare，也停止心跳重复触发这条入口。重新开启不打断正在发声的原生曲目；下一次选歌通过已有 loadOwned 顺序先建立所有权及静音门控，再取数据。开关状态新增“当前保持原生播放，下次选歌生效”，避免把启用偏好误说成已接管当前歌曲。

修改通过整包 JavaScript 语法检查及 ZIP 打包；修正后的开关文本和请求抑制尚待再次实机确认。本轮没有把这项检查扩展为弱网、全进程网络审计、整曲完整性或 Mac 实测结论。
