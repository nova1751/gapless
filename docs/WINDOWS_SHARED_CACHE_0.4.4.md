# Windows 0.4.4：歌曲区块共享缓存

## 已实现

播放、拖动和下一首准备共用带源身份的编码区块缓存。键包含账号范围、歌曲、请求音质和授权文件身份；不同档位或文件不混用。同一范围共享在途请求，重叠范围只读取缺口；一个使用者取消不会中断其他使用者。缓存采用访问时间淘汰，编码数据上限 64 MiB，并计入原有 512 MiB 总资源预算。

读取顺序为已解码 PCM → 已下载编码区块 → 网易云完整磁盘缓存/本地文件 → 当前授权网络源。原生磁盘缓存必须通过既有歌曲、MD5、档位、大小及完整度元数据检查；不读取未知有效范围的原生半成品缓存。插件仍不向网易云缓存目录写文件。

有有效索引且范围读取可用的 FLAC 改为按需准备：先请求最多 32 KiB 文件头，取得第一段可播 PCM 后停止初始读取，再准备当前播放位置附近约 8 秒的数据；剩余不足约 4 秒时继续补充。下一首先准备开头窗口，不再默认把两首全部下载、解码。Seek 优先于旧位置的后台准备；目标附近已解码则直接复用，已下载则复用编码区块。暂停后当前小窗口可以完成，随后不继续读完整曲。

没有索引、索引不在初始头部、范围请求不可用或超出单区块限制时，退回既有顺序读取路径；此路径仍可能读取整首。原生歌曲授权、音质、UI、采样转换和播放时钟接口未更改。

## 校验与生命周期

- 范围响应检查 206、Content-Range、文件大小和精确长度；解码继续检查帧位置、样本数、规格及错误。
- 若完整原生缓存的全部编码区块恰好仍在内存，就利用这些区块验证整首 MD5，不为计算 MD5 强行下载缺失部分。校验期间锁定相关缓存区块，避免淘汰造成预算外引用；失败触发已有恢复保护。
- 仅读取部分区块时，不宣称整曲 MD5 已验证。网络和缓存都是同一授权音源；没有低档音质兜底。
- 停止、换源、关闭和恢复撤销无效工作；关闭清空编码缓存。缓存只在当前应用会话存活，不新建永久歌曲库。
- Mac 未启用索引读取和区块缓存；共享代码新增逻辑受 Windows 的 overlapStreaming 开关限制，不能称为两端已经统一。

## Windows 实测

客户端 3.1.43.205627 / BetterNCM 1.3.4。

- Baptized In Fear 暂停后执行 229.176 秒 → 120 秒 → 229.176 秒：准备分别约 117 / 101 / 12 ms。返回曲尾前后缓存读取计数均为 13，编码缓存均为 2220005 字节，没有新增读取。
- 随后恢复播放，Open Hearts 预约提前约 2.999 秒，scheduledGapFrames=0，发生 boundary / claimed，无回退；暂停后活动节点为零、临时预留为零。
- 网络源 Moth To A Flame 播放 13 秒：初始请求 bytes=0-32767，后续均为精确范围读取；当前曲和下一首编码缓存合计 2854068 字节，没有整曲下载或后台整曲解码。两首 indexed-ready 分别为 153 / 224 ms，无回退。
- 临时接口检查验证共享读取、单使用者取消、重复读取零新增请求、音源隔离和容量淘汰；不新增常驻测试文件。
- 关闭开关后编码缓存、临时预留、Web 活动节点均为零，归还原生；检查后已重新开启。
- 修改文件语法、ZIP 打包及安装校验。未做新的系统音频回录，也未做 Mac 实机验收。

## 尚未统一的部分

本版统一的是插件自己的歌曲区块记录及读取调度，并复用原生已有缓存；并未让原生与 Web 双向共享新增磁盘缓存。原生写入接口、缓存索引和部分缓存有效区间尚未验证。

PCM 仍保留现有整曲 AudioBuffer 地址空间，受总预算约束；虽然只按需填充和解码，不能称为固定小内存环形缓冲。将其改成可淘汰的 PCM 分块需要同时适配播放时钟、可视化和恢复协议，本版没有把这一结构变更与缓存读取混在一起。任意手动上一首/下一首的宿主 Stop→Load 间隔仍不在本版已解决范围内。
