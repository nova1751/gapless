# Windows 0.4.0：首次播放的流式 FLAC 无缝衔接

日期：2026-11-15。客户端 Windows 3.1.43.205627 / BetterNCM 1.3.4。取代 0.3.1 的冷曲原生、缓存成对就绪才 Web 的入口策略；Mac 仍为 0.2.5 候选。

## 解决的问题

0.3.1 在冷曲起播时一直保持原生，而且要求当前与下一首已完整缓存才能准备。结果是两首先听一遍之后才容易进入 Web。现在受支持的 FLAC 从第一首开始增量解码，达到约 0.75 秒 PCM 就绪后即可出声；同一音频时钟提前准备和预约下一首，不再要求先播放两首。

未更改网易云的授权音源、音质选择、窗口按钮、歌词页或右上角开关。WASM 解码库打包在同一个插件内部，没有增加一个宿主插件或运行时 CDN 依赖。

## 音频路径

1. 启动安装控制桥、读取开关，不拦住初始化请求等待整首解码。
2. 有效 FLAC Load：匹配解码内存→完整网易云磁盘缓存/已授权本地文件→相同授权网络源。首次资源准备超过 1 秒则取消该 Web 尝试并放行原生；此期限不包括后续输出设备初始化，不能承诺总起播硬上限 1 秒。
3. 使用固定版本 @wasm-audio-decoders/flac 0.2.11（libFLAC WASM）增量解码。输入每段最多 32 KiB，约 4 ms 工作后让出主线程；不修改 CSP，不强开 Worker。
4. STREAMINFO 限制已支持规格：8/16/24-bit、单/双声道、8–192 kHz，并受资源预算约束。其他格式/规格回退原生，不降音质。
5. 先保留约 0.75 秒已解码数据；输出按原始采样率创建 AudioContext。分段 AudioBufferSource 使用同一时钟，提前安排约 2 秒输出；初始流式节点留约 60 ms 调度余量。
6. 整首解码及校验完成之后，已排程片段的后续部分直接接上完整缓冲，不重新起播、不切换后端。自然跨曲同钟预约；没有交叉淡化、静音裁剪。
7. 下一首通过网易云原解析器获得授权，后台按上述缓存优先级准备。FLAC 比较采样率、声道、位深；MP3 不再因位深字段为空一律拒绝，但仍用现有整首解码路径，编码延迟/填充尚未全覆盖。
8. 网络停滞、解码错误或缓冲不足通过现有恢复事务返回同曲原生位置。此异常回退不能承诺无断音；源不可用或下一首来不及准备时不制造无缝保证。

## 完整性和音质

流式模式不可能既在整首下载前出声，又在出声前完成整首 MD5。现在先匹配网易云授权身份与缓存元数据，检查解码错误及帧规格；完整缓存 MD5/总帧数/长度检查在读取结束时完成，失败即停止该流并恢复原生。此行为明确替代 0.3.0/0.3.1 文档中“完整 MD5 后才能输出”的策略，不能将首段就绪记成整首校验通过。

libFLAC 包装器原本以正满幅值转换正负样本。适配器先恢复 <=24-bit 的整数 PCM，再使用 Chromium 对应的浮点转换，避免更改负满幅比例。穷举 8/16/24-bit 整数范围验证恢复无误；Baptized In Fear 的 16-bit 双声道共 20,477,960 个样本与同源 Chromium OfflineAudioContext 完整解码逐样本一致（最大差值 0）。这是单曲解码证据，不是所有音源或原生/DAC bit-perfect 保证。32-bit FLAC 不走该转换。

## 控制与重试修复

- Stop→Play 没有新 Load 时保留曲目身份、从零重播；延后一个任务重新发 Load 完成通知，避免宿主清空 playId 后丢失进度和队列。
- 当前曲的原始歌曲 ID 和播放实例 ID 均可接收传输控制；仍核对当前选中曲目与宿主实例，旧曲命令不影响新曲。
- 暂停期间装载完成不会自动起播。重新启用重置失败状态。
- 预取异常清除失败候选，2 秒起指数退避，连续失败最多四次；解析器有 3.5 秒超时。成功/重新播放后重新计数，避免 selected 残留永久阻止重试。
- 停止取消候选工作；关闭后活动节点、缓冲及在途任务释放。

## 内存与剩余限制

当前是“增量起播＋有上限的整曲 PCM 缓存”，不是恒定小内存环形缓冲：沿用 512 MiB 管理预算、128 MiB 编码文件上限、最多一首可选最近曲。额外预留解码/输出片段空间，但不等于整个进程峰值上限。长篇高采样率音源可能回退原生。

当前资源任务仍串行，下一首一般在当前曲读取结束后开始；极短歌曲或弱网不保证首次无缝。后台标签页长时间调度停顿、设备切换、所有 MP3 编码器以及 24-bit 实际音源仍需更多覆盖。第一遍保证仅限受支持格式且下一首及时就绪，不是任意曲目/网络的绝对保证。

Mac 未接入这条流式路径。共享 AudioResources 的提前发布是 Windows 子类显式启用；Mac 沿用原有完整文件解码，仅通过语法/ZIP 包装检查。

## 验证

- 空 Web 缓冲、网易云磁盘缓存命中：首次装载 555 ms，从 0 起播，后台得到 Open Hearts，提前预约间隔 0 帧。
- 临时绕过磁盘缓存读取（没有删除用户缓存）：Baptized In Fear 首次网络装载 234 ms；Open Hearts 也由原授权网络源首次准备。没有要求先播放一遍。
- 同一次首次播放 Seek 到尾部验证 Baptized In Fear→Open Hearts 的自然 End/Load 接认，约 184 ms；没有重新播放两首。另一次原生网络源新曲 Wake Me Up 装载 110 ms（已有输出上下文）。
- 同曲重播后 playId 有效、从 0 起播；原始歌曲 ID 暂停后宿主 state=1、activeNodes=0。
- 注入一次下一首 download-timeout，约 2 秒后重试成功并预约。
- 装载中暂停保持暂停。关闭后 held/reserved/pending/activeNodes 均为 0，随后重新启用。
- WASAPI 48 kHz 双声道回录：一次曲间边界，回调错误 0；波形对齐后的边界附近 ±100 ms 没有近零段，前后相关位置误差跨度约 0.937 ms。另一次新曲分段播放，1 秒窗口的 1–5 秒位置偏移跨度约 1.653 ms。短窗口受周期性音乐误匹配，未用来判定间隙。两者均不是模拟输出或采样级硬件无缝证明。
- 本机当前隐藏窗口，未重新做完整视觉验收；未修改 UI 源文件。

原始音频和参考 PCM 只保留本机实验目录，不进入 Git。脱敏指标见 [记录](verification/windows-streaming-0.4.0.json)。
