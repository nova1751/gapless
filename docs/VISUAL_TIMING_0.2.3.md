# 0.2.3：频谱输入与动画时钟修正

2026-11-15，Mac网易云3.1.12（3444）。用户反馈0.2.2虽然恢复频谱，但变化频率和节拍触发时机与原生不一致。本版修正显示支路，音乐资源、解码、音频节点、音量、采样率策略和无缝预约算法未修改。

## 已确认的原因

1. 原生效果组件把收到过的最大PCM包长度同时用于后续分析调用。0.2.2按rAF间隔生成变长包，本次捕获400包为2880至4724字节，组件保留4736字节容量；较短包没有覆盖的尾部仍被分析。原生对照始终发送1600字节包。不能仅以“频谱已变化”认定输入协议一致。
2. 原动画保持30 fps，但绘制位置来自每150毫秒更新的UI进度，而PCM位置来自实际声音输出时钟。旧版147个绘制样本与输出位置的差值为约-327至+63毫秒，包含页面启动/任务延迟；这不是设备声学延迟的测量。

## 修正

- 每个显示包固定400帧，即48kHz双声道s16le的1600字节。不改原效果组件；一轮rAF按顺序交付若干小包，不能把它们合并成大包。组件分析长度因此也保持1600字节。
- 只分析已经到达输出时钟的完整小包。Seek、播放实例和控制代次变化丢弃旧样本；新节点尚未到达设备时不提前分析新位置。单轮最多6包（50毫秒），长时间阻塞跳过旧数据，不积压追赶。
- 原`_AERenderMV`和`_AEWebSetPlaybackPosition`仅在Web拥有播放、原效果订阅且页面可见时读取同一输出位置。原有30 fps、频谱算法、动画参数、资源、歌词组件和样式保留；不加动画定时器或音乐输出节点。原生恢复时原绘制参数直接放行。
- 显示采样异常不暂停音乐；包装只修改绘制时间参数，不调用Seek/Play/Pause，也不改系统媒体发布机制。

## 实机与用户确认

- 完整0.2.3包已安装、宿主注册并重载，实读运行版本0.2.3。
- 捕获3600个Web显示包，发送长度和原WASM分析长度均为1600字节。1173个播放中绘制样本与输出位置差值为-1.3至0毫秒，95%区间约-0.2至0毫秒；只表示软件取样时钟一致，不包含显示器、DAC、蓝牙或人的感知延迟。
- Seek70、Seek160后显示位置跟随新声音；暂停后计数7732保持稳定，继续后恢复采样。
- 实际Baptized In Fear→Open Hearts跨曲保留同一音乐时钟代次2、预约间隔0帧。新曲的显示数据、标题、歌词和原环形频谱已观察更新。
- 恢复原生时Web采样停止，300毫秒内收到21次原生PCM通知，分析容量仍为1600字节。
- 短时记录累计19119个小包，平均同步处理约0.377毫秒/包，单轮最大5.4毫秒，包含临时诊断开销；不据此保证所有设备都无卡顿。
- 验证后恢复原曲Baptized In Fear，暂停位置115.9762秒。用户随后继续播放，并确认“已恢复正常”。临时回调包装、取样记录及音频副本已清理，保留用户最新播放意图。

脱敏记录见[实机数据](verification/mac-visual-timing-0.2.3.json)。没有新增测试、全仓静态检查或应用构建；完成增量JS语法、源码审查、包CRC/SHA、安装/解压一致性和相关实机场景。

## 边界

显示PCM仍是转换副本，不保证每个分析值与原生逐点相同；其他特效资源、高采样率、设备切换和长时间负载未全部覆盖。已确认当前效果恢复正常，不扩大为全部原生特性等价。macOS控制中心进度回跳是独立问题，仍未解决。

Windows只更新[实施方案v14](WINDOWS_CONTINUOUS_WEB_AUDIO.md)。应实查它自己的固定包长度、分析接口和绘制时钟，不能复制Mac的400帧或模块编号；没有Windows运行包和实机验收。
