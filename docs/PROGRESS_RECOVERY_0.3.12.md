# Mac 原生回退后进度停在 00:00（0.3.12）

日期：2026-11-17；基于 main `924f6d8`。网易云 Mac 3.1.12（3444），BetterNCM-mac 0.1.7，管理入口 1.2.1。Mac 源码、安装包、运行文件及实际页面均为 0.3.12；Windows 保持源码 0.4.15、既有安装／运行 0.4.14，本轮未操作 Windows。

## 问题与原因

Out of Time 界面进度停在 00:00，原生位置却已到 183.7475 秒。原生进度事件正常传入 SDK，插件桥未拦截；客户端 `isLoadingFirst` 和模块 84 的加载门控一直为 true，使进度视图不接收正常上报。

另确认宿主 injector 进程已退出，状态文件仍在、缓存 API 端口没有监听；浏览器请求本机文件服务报 `Failed to fetch`，导致多首歌回退原生。尚未确定宿主退出原因，不能把它归为歌曲网络或 FLAC 损坏。

旧恢复路径把所有缓存失败都设为需要重新选曲，再调用 SDK `AudioPlayer.play`。该方法使用 `overwriteRegisterCall("Load", "audioplayer", callback)`，会覆盖仍待完成的原始 Load 回调。嵌套加载恢复了声音后，原始客户端播放任务仍未结束，加载标记和进度门控因此没有清除。

## 修正

- 记录当前实例未完成的 SDK Load，直到其原始回调结束；缓存失败不再强制重新选曲。
- 有待完成 Load 时，使用其原有授权资料执行原生 Load／Seek／播放意图恢复，之后完成原始回调。没有待完成 Load 的页面恢复／开关关闭仍可使用既有 SDK 重建路径。
- 本地曲接认验证失败也标记原始 Load，防止同类嵌套加载。继续使用实例与代次检查，记录 `recovery-load-route` 的布尔路由信息，不记录音源 URL。
- 用宿主正常 attach 流程恢复唯一 injector，按宿主原配置重载页面。保留旧包和用户暂停位置；未修改宿主代码、安全策略、采样率、音量、解码或预约算法。

## 实机证据

安装与包内容一致，当前完整 0.3.12 页面已运行。恢复宿主后本机缓存 API 正常响应，Out of Time 有效缓存读取与目标位置解码完成。

临时对 Out of Time 的一次资源取得注入 `native-only-cache-probe-unavailable`，模拟加载中读取失败；仅影响该次操作，方法随后恢复。结果：`pendingSdkLoad=true`、`sdkSelection=false`，原生恢复约 48 ms；客户端 `isLoadingFirst=false`、进度加载门控为 false，SDK 原生进度为 9.05 秒并继续推进，窗口的进度条和歌词页面也推进。48 ms 只表示这次协议恢复耗时，不代表声音无缝。

暂停并通过原生 SDK Seek 恢复原曲 183.7475 秒，返回 code 0、实际保持暂停。随后用户自行切换并播放 Starboy，保持其新播放意图。未新增测试用例、全量静态检查、应用构建、音频回录或 Windows 实测；仅修改文件语法检查、ZIP 完整性、实际加载／回退协议与界面观察。必要数值见 [机器记录](verification/mac-progress-recovery-0.3.12.json)，包 SHA256 见 [版本表](versions.json)。

## 边界与 Windows 建议

本修正解决已复现的加载回调丢失和进度卡零；宿主服务以后若再次退出，缓存不能读仍需回退原生。本轮没有自动重启宿主、改其常驻策略或证明退出根因已消除。控制中心原有短时进度回跳、异采样率和源故障的无缝限制保留。

Windows 本轮没有移植此 Mac 适配代码。推荐继续保证一个选曲事务只完成一个原始 Load，恢复不得覆盖其订阅，源准备实例的回调不得清理或更新主曲目状态；实际错误回退、加载中暂停与后续 Seek 应在 Windows 独立验证，不能将本 Mac 注入结果视为 Windows 已验收。
