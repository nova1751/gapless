# 0.2.1：优先保留音源采样率

这是0.2.1采样率保护的历史检查。当前版本见根README；0.2.2新增的[可视化PCM](VISUAL_PCM_0.2.2.md)只处理显示副本，不改变这里的音乐采样率策略。

用户优先要求尽量不影响音质。0.2.0输出上下文由第一首确定采样率，后来96kHz缓冲可能进入44.1kHz上下文。虽然仍选择网易云原授权音源，没有改音质档位，这条路径会由Web Audio重采样。0.2.1去掉这次插件级跨率转换。

## 最小改动

- 原有音源选择器、音质档位、缓存和解码管线保持原样。源规格与解码缓冲采样率、声道数不符时拒绝Web播放。
- `PlaybackClock.matches`要求源、缓冲、输出上下文采样率一致。下一首不同采样率时只预加载，不预约进当前时钟；同采样率仍按同一PCM结束时刻开始。
- 正常End/Load已先取消预约并停止旧节点。`open`只在没有活动或退休节点时关闭旧上下文，并按下一首源采样率创建输出。异步关闭后核对代次；有新Load时拒绝旧任务继续。
- 输出不支持所需采样率或启动失败时，沿用已有恢复事务回到相同授权原生源，不换低音质，不增加调音设置。
- 不新增CSS、歌词逻辑、EQ、混音、静音裁剪或系统进度纠偏。没有更改macOS设备采样率。

## 取舍与限制

同采样率的专辑仍可连续预约。不同采样率边界需要关闭、打开和等待输出时戳，可能有短间隔；优先保留音源规格，不把此边界说成完全无缝。首次从原生进入Web、异常恢复及不兼容设置仍可能交接。

AudioContext只能有一种采样率。[Web Audio规范](https://www.w3.org/TR/2021/REC-webaudio-20210617/#AudioContextOptions)要求支持指定采样率时按其创建，但输出设备采样率不同时仍须重采样。因此此改动避免的是插件上下文中的跨率转换，不保证设备比特直通。没有原生/Web输出波形的音质等价验证，也没有听音结论。

Web使用float32 PCM。16/24位整数PCM的归一化样本可由float32表示，但实际解码器、音量处理、系统输出及更高精度音源仍不能据此证明比特等价；不把“使用float32”本身等同于已发生可听降质。原生私有音效/空间等处理仍受已有兼容性检查限制，未重新实现。

## 本轮验证范围

实机Chromium的一次静音诊断确认：44.1kHz上下文拒绝96kHz条目；有活动节点时拒绝切换，旧节点及上下文保持；停止节点后创建96kHz运行上下文，44.1kHz条目不再匹配。诊断的全部节点/上下文已清理。这只验证输出时钟和保护机制，不是真实Hi-Res音乐、设备格式或音质回录。

当前音乐播放期间只替换原时钟类的`open/matches/status`方法，当前曲目、位置、播放意图、时钟代次和下一首预约不变。完整0.2.1包已安装并重新注册，但不刷新当前页面：当前0.2.0协调器的预约入口也调用新`matches`，所以采样率保护已生效；新包的混合采样率诊断事件待下次页面加载生效。完整包混合采样率音乐、快速跨率切歌、休眠和设备切换尚未实测。

代码语法、包CRC及安装文件SHA已核对；详情见[验证记录](verification/mac-audio-quality-0.2.1.json)。0.2.0系统控制中心回跳及按钮闪动仍未解决，本改动不扩大系统控制流程。
