# Mac 0.3.8／Windows 0.4.12 插件管理对齐

基于 main `a9cd8b8`。PC 新改动是统一右上角入口和 BetterNCM 管理界面，未修改 0.4.10 音频链路。Mac 采用相同信息层级，但保持自己的宿主兼容边界。

## 对齐范围

| 项目 | Windows 0.4.12 | Mac 0.3.8 |
|---|---|---|
| 右上角 | BetterNCM 入口 | 宿主原插件按钮，位置和原生按钮样式不变 |
| 默认弹层 | 无缝开关、状态、管理插件 | 无缝开关、状态、管理已安装插件 |
| 管理 | 宿主 BetterNCM 管理页，默认无缝配置 | 宿主认证 API 返回的已安装插件与内置项 |
| 市场 | 使用已有市场及其网络／兼容规则 | 通用市场默认隐藏，不安装未验证的 Windows 原生插件 |
| 版本 | manifest／打包运行版本 0.4.12 | 安装清单标签 0.3.8；运行版本由 manifest 注入，悬停显示两者及不一致提示 |
| 控制 | 沿用原插件开关 | 沿用原插件捕获处理器与 host enabled API，保存串行化 |
| 样式 | 弹层和打开的管理页局部样式 | 独立弹层、原宿主开关；未修改主窗口和歌词页 CSS |

Mac 新增 `mac/host/plugin-menu.js` 和安装脚本，独立 MIT 实现；使用宿主原有自动发现 prelude 能力，不复制或改写 GPL 宿主原文件。只调用认证的 installed/enabled/uninstall 接口，不请求远程市场。页面关闭或弹层关闭停止轮询；卸载仍需原流程确认，本轮没有执行卸载。

兼容提示来自宿主，不补造一个「所有插件均可运行」白名单。当前本机列表是内置歌词窗口（关闭）与无缝播放；未安装其他插件来扩展音乐／歌词行为。

## 首次关闭恢复修复

页面重载后，Web 可恢复暂停曲目，而原生尚未注册 Load。原有同曲选曲路径走 Resume，八秒等不到 Load，进度丢到 0。完整强制选曲也会在恢复结束后再次发布 Playing／旧 Seek，因此最终实现没有使用它。

同曲资料和客户端 SDK 检查通过时，用 SDK AudioPlayer.play 建立真实 Load；只拦住该重建动作自动发出的首次 Play，立即确认给 SDK，不向原生输出下发音乐。SDK 完成后，真实原生 Pause → Seek → 最新播放／暂停意图恢复。重建的迟到／重复 Load 不能再次自动 Play，新真实 Load 清除保护。当前行变化时仍保留原选曲分支；未知 SDK 保持显式原生失败回退。

实机以暂停 Open Hearts、10.153351 秒且无 onLoad 注册复测：恢复确认约 2549 ms，原生位置 10.15 秒，应用状态 Pause，Web 音乐节点 0；管理视图切换时开关仍锁定。再开启、真实点击播放／暂停、SDK Seek 正常，最终恢复原位置暂停。解码、采样率、音量、歌词、频谱和曲间排程未修改。

## 安装／回退与证据

Mac 包 0.3.8、runtime manifest/player/startup 全部字节一致；菜单 1.0.0 的安装文件与源一致，旧 0.3.7 包备份在活动目录之外。[哈希和范围](verification/mac-menu-0.3.8.json)，[统一版本](versions.json)。

菜单扩展只增加宿主 `src/prelude/gapless-plugin-menu.js`。`python3 mac/install-menu.py --remove` 在下次重载恢复原菜单，播放器包不随之卸载。宿主升级可能移除扩展，需再次核对接口再安装。无缝开关关闭恢复原生；包回退先正常退出再替换同 slug 活动包。

Windows 0.4.12 安装和日常 UI／日志结论来自上游状态记录。本轮没有 Windows 实机、0.4.12 包哈希或新音频回录。原始 [0.4.10 带哈希记录](verification/windows-candidate-install.json)保留原版本；[历史状态快照](HISTORY_STATUS_2026-11-17.md)保留上游 0.4.11／0.4.12 说明。

验证仅覆盖改动相关语法、ZIP、宿主 API、菜单样式、开关及恢复／短时播放；未运行全量静态检查、应用构建或新增测试。没有重新验证所有音源、全插件市场、设备输出／DAC 音质、系统控制中心回跳或极端网络条件。
