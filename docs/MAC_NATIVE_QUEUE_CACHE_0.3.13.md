# Mac 原生队列、后台缓存和启动恢复（0.3.13）

日期：2026-11-22；基于远程 main `ffacf07`。Mac 3.1.12（3444）＋ BetterNCM-mac 0.1.7，管理入口 1.2.1。Mac 源码、包及实际页面为 0.3.13，旧 0.3.12 包保留。Windows 0.4.21 原样同步，本轮没有 Windows 实机操作。

## 改动

- 使用实际 Mac 原生队列选择函数，支持已确定下一首的心动模式；检查顺序字段、唯一性和队尾，保留网易云随机顺序及单曲循环规则。相邻源上下文不变时，修改队列编号不撤销有效预约；新的源上下文仍使旧预约失效。
- MD5 每约 4 ms 通过 MessageChannel 让出，避免后台嵌套计时器等待。合并两处索引路径的整首校验；尺寸、MD5、取消和清缓存代次约束保留。没有放松完整性或修改音频样本。
- 用户目录从宿主已有 `app.datapath` 元数据识别，不再枚举桌面、文稿、音乐文件夹。自定义宿主目录无法推导用户目录时，使用网易云提供的绝对缓存路径；两者都没有时明确回退原生。
- 索引读取复用宿主已有挂载文件的异步流式通道，避免 `fs.readFileText` 的同步文件打开阻塞整个宿主。读取至多 1 MiB，严格核对 Range 与长度，并复核读取前后大小和修改时间；文件增长时重新取得有效版本。索引没有执行音频 XOR，不写 UC／IDX 或第二套音乐缓存。
- 启动能力检查依赖播放接口及原生数据选择器，不依赖歌词页模型。延迟初始化的恢复快照只在没有新实例或控制时使用；新 Load 的较新控制优先。恢复失败时保留未完成目标及意图，新的原生操作会使旧目标失效。若同一原生实例仍可 Seek，先恢复目标再恢复传输意图，内部 Seek 与 SDK 用户请求隔离。暂停状态的原生选曲恢复失败时，使用网易云原有的暂停恢复流程清理加载状态，复核实例、控制代次和最新播放意图；不直接修改加载标记，也不停止真实音频后端。

## 证据与当前状态

隔离运行生产方法及真实 Mac 选曲函数，心动相邻项、队尾、追加、源变化、重新编号、随机顺序、单曲循环及重复项拒绝检查通过，没有修改用户实际歌单或播放模式。

同一 2 MiB 合成输入，新 MD5 路径两次约 69／63 ms 完成；旧路径约 38.8／40.7 秒才响应先前请求的取消，未完成校验。两者不能计算成真实歌曲起播加速倍率。损坏数据、主动取消和清理代次拒绝检查通过；延迟快照、近期／较晚控制及恢复失败后的新 Seek 优先检查通过。

线程采样确认当时宿主主线程阻塞在 `ReadFileUtf8 → uv_fs_open → __open`。普通停止失败后重启了已确认的宿主进程，通过正常 attach 加载新包；没有修改宿主源码、安全策略或系统授权。具体阻塞文件路径未取得证据，不能把所有文件读取失败都归为目录枚举。

改用异步索引通道后宿主元数据接口返回 200；已知宿主文本文件的 Range 读取与内容核对通过，自定义目录及尺寸拒绝检查通过。真实歌曲缓存此次仍读取失败，失败原因尚未查明。原生 Seek 曾返回 code 0、位置 218.15663492063504 秒；最终重载后自动恢复约 218.16 秒、暂停，客户端加载标记清除，SDK 进度与原生位置一致，Web 音乐节点为 0。安装包、准备的运行文件和实际页面版本一致。

界面工具报告 `cgWindowNotFound`，无法完成本轮频谱、歌词、控制中心或真实心动跨曲验收；没有声音回录。不能将隔离检查当作真实无缝播放已验证，也不能宣称所有卡顿／缓存问题已消除。完整数值见 [机器记录](verification/mac-native-queue-cache-0.3.13.json)，包哈希见 [版本表](versions.json)。

本轮仅做修改文件语法检查、代码审查、必要隔离诊断、ZIP 与安装一致性、原生恢复确认；未新增测试用例、执行全量静态检查或应用构建。音乐授权、档位、音量、采样率、歌词及频谱算法未改。
