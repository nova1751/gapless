# 0.1.2 进度回跳与副作用审查

日期：2026-11-14；目标为网易云 Mac 3.1.12（3444）、BetterNCM-mac 0.1.7。诉求仅限无缝衔接，沿用原生音质选择、音量、队列及 UI。0.1.2 已更新本机安装包；Windows 仍只有实施方案。

## 结论

0.1.1 的普通 Seek 检查不足以覆盖快速控制，确实存在回调丢失、串错请求和暂停意图被覆盖的问题；这些会造成进度同步异常，不能承诺旧版无副作用。0.1.2 修正这些竞态并收窄无收益的接管范围；Seek 只短暂推迟接管，不让整首退出。已接管状态的原生 SDK 检查及进度条逐帧记录未出现“目标→旧位置→目标”；这只覆盖记录中的场景，不代表所有鼠标手势、系统事件和边界竞态已验证。

当前精简范围为：准备当前和可信下一首、共享音频时钟预约、必要原生状态同步、取消及原生恢复。一项宿主开关沿用已有样式；没有新增播放器面板、音质入口、歌词布局、主题、淡化或静音裁剪。

## 已修正的问题

| 问题及原因 | 0.1.2 行为 | 证据 |
|---|---|---|
| Seek 后马上暂停，control revision 改变使延迟通知被丢弃；后一次 Seek 又可能完成前一次订阅 | 每个已接收请求都完成自身响应；过期实例返回失败。音频位置立即采用最新意图，响应不因暂停而丢失 | 修正前记录第一次请求 350 ms 内未完成，后续收到第二次 token；修正后自身 token/60 秒完成 |
| Mac SDK 在 RPC 后才订阅 Seek，而且未按 token 过滤；快速确认多个 RPC 导致订阅串错 | RPC 确认和对应 Seek 通知串行发送。进度发布时读取当前音频位置，不回放旧请求位置；恢复期间也使用相同策略 | 暂停时连续请求 100/200 秒分别完成自身 token；进度只采用最后位置 |
| 首次接管已暂停原生，再发生 Seek/暂停使后续等待提前退出，可能留在 pausing；原生 Seek 事件也可能早于 SDK 订阅 | finally 等待进行中的原生 Seek，并按最新意图解除原生暂停。原生完成事件先缓冲，再交付 SDK | 接管中途 Seek 正确返回自身 token/75 秒；取消接管并继续原生 |
| 宿主通过进度增加推断“正在播放”，暂停时大幅向前拖动可能让 UI 变成播放 | 位置更新后同步一次真实暂停状态；暂停不重复发送进度心跳；保护插件恢复后的原生暂停进度 | SDK 暂停 Seek 后 1.4 秒仍为暂停，活动音频节点为零 |
| 恢复时原生 onLoad 自动发 play，覆盖用户的暂停意图；直接 load 和队列选曲都会触发 | 两种恢复加载路径都识别该自动播放工作流；用户暂停意图独立保存，恢复完成同步真实状态 | 中间失败记录保留；最终恢复期间连续 Seek 记录验证 |
| 当前曲目解码后就接管，即使下一首不可信或无法准备，没有无缝收益也替换了后端 | 当前与可信下一首均已解码、规格兼容后才接管；每次等待后复核队列及候选。已拥有时失去可信下一首则恢复原生 | 下一首超出文件限额：当前已解码，仍由原生播放；兼容两首均解码后才出现 takeover |

## 保留与删减

保留源指纹/授权档位复核、内存预留、任务取消、预约撤销、实例及代次保护、单次 End、原生恢复事务。这些不是额外产品功能：删除会增加错歌、双后端出声、停声、过期请求改进度或内存峰值风险。原生歌词获取仍用于接管后的正常同步，渲染和样式不变。

删去暂停时的重复进度发送及歌词异步完成后的强制进度刷新。原生暂停、未知下一首/模式时不主动解码；当前解码任务未结束时保留它，避免“下一首尚未就绪”被误判为应清理而循环取消任务。候选准备失败保留原生后端；没有新增调参或诊断面板。

本轮中间版本曾让首次准备/接管中途拖动后的整首曲目保留原生；用户反馈无缝失效后确认这是过度限制，已撤销。当前只等待原生 Seek 完成及 400 ms 位置稳定窗口，保留已解码资源并自动重试接管。实测初次 Seek 到 200 秒后重新接管，并完成 Baptized In Fear → Open Hearts 的真实预约边界和原生接认。已接管时的普通 Seek 仍取消旧预约、立即采用目标位置并按新结束时刻重新预约。

## 无法消除或尚未验证的代价

- 接管后的解码/输出经过 Web Audio。保持原生选择和授权音源，并不证明设备数字输出、原生声音包络或所有收听统计完全等价；本版不额外做淡化来模拟原生 Seek。
- 后台完整获取并解码曲目会增加流量和内存。本次两首 44.1 kHz 双声道缓存约 182 MiB；512 MiB 是插件管理预算，不包含浏览器、解码器、设备的全部峰值。
- 首次原生交接与异常恢复仍需等待，不承诺这些过程零间隔；随机/推荐、重复 ID、不同采样率、权限/格式/音效不兼容等保持或恢复原生。
- 当前队列 Open Hearts → Moth To A Flame 为 44.1 kHz 无损到 176.4 kHz / 24-bit Hi-Res；后者编码文件约 133 MiB，超过 128 MiB 单文件上限，且两首采样率不同。该边界不能保证无缝，不强制降低下一首规格以绕过限制。
- 作品留白原样保留。MP3 编码器填充、声卡数字输出零间隔、系统休眠/设备变化及全部边界手势未完成实机验收。播放时钟预约参数为 0 帧间隔不等于数字环回测量。

## 验证材料与方法

- [seek-before-fix.json](verification/seek-before-fix.json)：0.1.1 丢失/串错完成通知的复现。
- [seek-after-fix.json](verification/seek-after-fix.json)：SDK Seek+暂停、暂停时快速 Seek、播放中向后 Seek；含真实进度条动画帧采样。
- [seek-takeover-race.json](verification/seek-takeover-race.json)：人工扩大位置查询等待窗口，实际原生暂停期间触发 Seek；并非新增测试用例。
- [restore-paused-before-final-fix.json](verification/restore-paused-before-final-fix.json)：本轮中间失败，直接恢复 load 的自动播放覆盖暂停；保留以说明修正依据。
- [mac-0.1.2-scope.json](verification/mac-0.1.2-scope.json)：候选超限时继续原生，保留音质选择和音量。
- [mac-0.1.2-final.json](verification/mac-0.1.2-final.json)：最终源码运行，两首先解码后接管、Seek+暂停及恢复期间连续 Seek。
- [seek-rejoin-boundary.json](verification/seek-rejoin-boundary.json)：后续撤销整首退出限制后，原生 Seek 完成、自动接管及实际跨曲/原生接认；包含结束时恢复暂停位置。
- [cross-rate-source.json](verification/cross-rate-source.json)：原生签名 API 及 FLAC 头部规格观察，只保留 ID/级别/大小/规格，不保存 URL。
- [PACKAGE_SHA256.json](verification/PACKAGE_SHA256.json)：最终源码、ZIP 插件与安装包的一致性。

以上为真实客户端的原生 SDK/桥协议操作和必要字段观察；没有改写 DOM 触发进度拖动。CUA 观察首页与原生播放条样式，并用真实键盘输入放行 AudioContext。鼠标自动拖动尝试没有可靠进入 Seek 路径，因此不记为通过，也不声称完整鼠标拖动验收。

仅运行变更 JS 语法检查、ZIP/源码一致性、JSON 和局部差异检查；没有新增测试用例，没有执行全量 lint、TypeScript 检查或应用构建。上版歌词、开关及常规恢复证据见 [0.1.1 历史记录](REMEDIATION.md)。Windows v4 方案已同步这些控制和接管要求。
