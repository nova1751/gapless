# 0.1.1 修正与验证记录

这是 0.1.1 的历史验收记录。当前版本及进度竞态、接管范围的后续修正见 [0.1.2 副作用审查](SIDE_EFFECTS_REVIEW.md)，不能把这里的普通 Seek 验证理解为已覆盖快速控制竞态。

日期：2026-11-14。目标客户端：macOS 26.6.2 arm64、网易云音乐 3.1.12（3444）、BetterNCM-mac 0.1.7。

本版替换已安装的 0.1.0。历史问题及原始证据保留在 [审查报告](MAC_GAPLESS_AUDIT.md)；Windows 是实施方案，尚未提供 Windows 可运行包。

## 实机发现的额外协议细节

原生指定队列行流程会先发送 `audioplayer.stop`，其中 ID 为空。这是选曲工作流的清理命令；恢复期间若让它清除插件代次，原生会从头播放。本版仅在恢复事务内接住此类清理；用户选另一首的 Load 仍可打断旧事务。

刚 Load 完成的原生后端已经暂停，再调用 pause 会有 RPC 完成但可能没有新的 PlayState 事件。恢复等待 RPC 即可，不能等不存在的事件而超时；首次从正在播放的原生后端接管仍等待 pause 状态确认。

`playing.resourcePlayingQuality` 是当前曲目的实际档位，不能当成用户配置。用户选择读取 `setting.quantity.listenReg/listenAnon` 和原生 Load 的 `soundQuality`；某首没有 Hi-Res、原生返回 lossless 时不会擅自改用户的 Hi-Res 选择。

## 仍需保留的限制

1. 只保持原生音质选择和授权音源，不承诺与原生输出比特相同。Web Audio 的 PCM 为 float32，系统/设备仍可能转换采样率。512 MiB 是插件管理预算，不能代表 Chromium、解码器和驱动的进程峰值。
2. 不同采样率、多声道、不能解析的格式、超预算、试听/MV/电台、非 1 倍速或已启用受保护音效的边界使用原生。0.1.1 对随机/推荐、重复 ID 只保证不预约；0.1.2 才要求这些模式保持原生后端。不能宣称这些边界均无缝。
3. 保留作品留白，不裁剪静音、不交叉淡化。MP3 编码器填充以及数字输出零间隔尚未做回录/数字环回验证。
4. 首次原生与 Web Audio 交接、异常恢复会有交接时间；不将它们称为已预约曲目边界的零间隔。Web Audio 暂停/开始的声音包络与原生 playFade 可能不同；本版不修改该原生设置。
5. getPlaybackInfo 继续交给原生，设备格式未测；原生 parked 后端的该接口不代表当前 Web Audio 的播放位置。状态中的 deviceFormat 明示 unknown。
6. 保存到新页面的听音基数在插件拥有播放时准确；纯原生期间未被查询的最后一段听音时间不通过异步卸载查询补齐。异常刷新、系统休眠和设备切换仍需更长实机覆盖，不能保证所有收听报表与原生完全等价。
7. Windows 没有实机环境，不能宣布 Windows 功能已达标。共享时钟与资源管线已实现；控制、恢复和宿主开关目前仍在 Mac 适配器中，移植时必须继续抽取共享，避免两套逻辑分叉。

Web Audio 机制依据：[W3C Web Audio 推荐标准](https://www.w3.org/TR/2021/REC-webaudio-20210617/)。
