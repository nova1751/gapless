# Mac 原生与 Web 实际输出对照

2026-11-17，在已安装 Mac 0.3.7 / 网易云 3.1.12 上，对同一首 Baptized In Fear 分别启用和关闭无缝开关，采集实际应用音频。结论：**本次响度和波形非常接近，但没有证明原生/Web 最终输出逐样本完全相同，也没有证明 Web 有可听音质下降。** 没有更改播放器实现。[脱敏数字记录](verification/mac-native-web-output-ab-0.3.7.json)。

## 输入与实际后端

两条路径沿用同一原生授权 FLAC：16-bit、44.1 kHz、双声道，实际档位 lossless。原生 Load 保存的 MD5、授权源选择器的 MD5 和只读缓存还原后的编码文件 MD5 均为 `cad47df6dd03b5faa82ffc244f6a99c1`，文件大小 27,081,483 字节。没有另选低档音源。该文件此前独立解码的 20,477,960 个 float32 样本与校验通过的 Apple 参考相同，[先前原文件 PCM 验证](PLATFORM_AUDIO_REVIEW_0.3.7_0.4.10.md)不替代本次播放输出对照。

实际 Web 发声时 ownsPlayback=true、两个播放节点、源及上下文 44.1 kHz；关闭开关后 enabled=false、ownsPlayback=false、节点为零，并收到原生 Play。原生恢复使用当前同一份 Load 元数据。两条路径的界面音量均为 0.48，系统音量显示 56%，变速为 1；应用状态里的音效、响度均衡、杜比、增强及空间音效均关闭。没有修改这些偏好。原生淡入淡出保存值仍为 true，比较避开起播约三秒，只分析稳定区间，不验收起播淡化包络。

本机默认输出设备名义采样率重新查询为 **48 kHz**，没有修改设备设置。[Web Audio 规范](https://www.w3.org/TR/2021/REC-webaudio-20210617/#dom-audiocontext-audiocontext)要求上下文与设备异率时在输出阶段重采样。输入、音量和最终输出采样率相同，不强制原生与浏览器采用相同的插值、转换和舍入实现；采集时钟的相位也不是相同参数的一部分。

## 采集与比较

ScreenCaptureKit 只注册 `.audio`，过滤网易云应用，取得 48 kHz 双声道 float32 数字音频。权限此前已存在，没有申请新权限或采集麦克风、截图。所有录取 PTS 连续，没有大于一采样点的缺口。此位置是应用音频采集路径，**不是声卡模拟回录，也不是 DAC 或蓝牙编码后的信号**。

从 100 秒位置各录取原生两次、Web 两次。第一次 Web 录取因 UI 起播迟到只有 0.284 秒有效声音，排除并重录，未拿它比较。原生 SDK 的 Seek 位置已应用，但确认等待超时，因此不直接假设两次原生起点完全相同，而通过实际波形找出共同音乐区间。

用双声道归一化交叉相关确定整数偏移，再用带前后留量的 FFT 插值拟合一个共同的亚采样偏移，拟合一个双声道共享的标量增益。四秒模板两端各去掉 1024 帧，最终每声道比较 189,952 帧、约 3.957 秒。没有拟合变速、EQ、降噪或修改播放样本；同后端重复录取作为方法基线。

SNR 表示两份录取之间的相减残差，**不是播放器本身的信噪比或音质评分**。原生/Web 交叉比较的残差有时大于、有时小于同后端重复录取，不能据此给两种引擎排音质高低。仅按整数偏移对齐时，同后端也几乎所有样本不相等；亚采样对齐后的残差也不为零。这份证据没有达到逐位相同，亦无法把非零残差全部归因于播放器：输出转换、采集相位及插值比较方法都在链路内。分频残差诊断也保留在机器记录，未用低通过滤后的结果冒充全带宽一致。

## 能确认和不能确认的事

能确认本例两端使用相同原文件，已有原 PCM 无损证据；本次实际输出的最大增益差小于 0.0005 dB，波形相关性超过 99.995%。没有发现必须修改播放器音量或解码才能解释的明显差异。不能确认“所有歌曲、所有音量、所有设备输出一定相同”，也不能从本次录取推导“完全听不出差异”。没有盲听或新的真实 Hi-Res 输出对照。

若要证明某个条件下的逐位一致，需要能在明确且一致的数字位置同步取得两条路径输出，并控制实际增益、采样率转换和时钟相位；当前接入没有可用的网易云原生混音前 PCM 同步 tap。参数相同是必要条件的一部分，不能代替结果校验。有限的输出对照也不构成普遍保证。
