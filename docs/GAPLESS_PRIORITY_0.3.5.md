# Mac 0.3.5 / Windows 0.4.7：无缝开关优先

2026-11-16，修正 `61f837f` 中把原生音效设置作为无缝门槛的错误优先级。Mac 0.3.5 已安装；Windows 0.4.7 为同步源码候选，未实机安装。

## 行为

开启无缝后，对受支持音源使用连续 Web 输出。原生淡入淡出、杜比、EQ、音量均衡、空间音频、音频增强和变速选项不再使插件交还原生。无缝输出保持源采样率、原音量、1x 时间轴，不执行这些原生专属处理；没有为它们加入新 DSP、混音或淡化。

采用运行策略覆盖，不改写保存的用户偏好。原生设置页仍可显示保存值，它不是当前 Web 输出已执行该音效的证明。关闭无缝后交回原生，原生继续读原来的设置；无需用户手动关闭淡入淡出，也无需配置恢复日志。开启期间改变这些偏好也不会因为设置开关而退出无缝。诊断用 `nativeAudioPolicy` 与 `suppressedNativeAudioSettings` 表达实际策略。

音质选择、授权取数、缓存、音量、歌词和频谱不变。试听/视频、无法取得或解码的音源、未知版本以及未验证的设备路径继续保留故障回退，不能因为“开启”就伪造权限或降低档位。不同采样率仍重建输出，不承诺这些边界无间隔。

## 本轮确认

- 真实 Mac 0.3.5 在原 `playFade: true` 下接管并播放。用户沿原队列选曲及 Seek 后，Baptized In Fear 自然到达曲尾、跨至 Open Hearts：预约间隔 0 帧，接认约 155.8 ms。接认时间是 UI/协议跟进时间，不是声卡静音时长；本轮未新增设备音频回录。
- 实际宿主开关关闭：同曲 71.5601 秒交还原生，继续播放，Web 节点归零、原生静音门解除。再次开启：同曲约 114.3794 秒重新接管，保持播放，淡入淡出仍保存为 true，Hi-Res 偏好仍为 1999。切换开关时仍有原生/Web 握手时间，不把这个过程称为零时间。
- 实际设置动作把淡入淡出改为 false、true，均保持 Web 所有权和播放中，未触发原生设置恢复；已恢复初始 true。原生 2x 请求被接住，Web 保持 1x，未交回原生。音质配置内容不变。
- Windows 实际 `source.snapshot` 的临时执行：七类原生设置全部开启时，无缝模式仍 capable；关闭时继续按原生偏好；试听/视频保护保留，输入状态未改写。该结果不是 Windows 实机或声音验收。
- 原有播放器、列表和宿主菜单样式正常；实际菜单 0.3.5 开关关闭及重新开启均已观察，最终已开启。用户验证期间自行改变歌曲和进度，没有用旧的暂停恢复快照覆盖这些新操作。

最后一次宿主热重载未完整初始化播放模型，界面保留旧画面、插件等待能力；正常退出重启后恢复。沿原队列恢复重载前最新的 Moth To A Flame、约 131.8231 秒并继续播放，回到原列表，实际运行的最终包已再次核对。没有将这次宿主重载异常写成已解决或全程无问题；本轮没有扩大为重写宿主重载机制。
