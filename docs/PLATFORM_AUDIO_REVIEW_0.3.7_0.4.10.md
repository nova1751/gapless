## 修正 Windows 多余的规格门槛

Windows `prepare` 在两份资源各自通过解码、源身份和规格检查后，仍要求两首 rate/channels/codec/bits 全相等，否则丢弃下一首并停止准备。Mac 在此处没有这个门槛。16-bit 与 24-bit FLAC 已分别无损转成 float32 PCM，不需要为了预约再次转位深；声道配置也由各首缓冲保留。不同采样率则应保留已准备资源，到下一次 Load 重建输出，避免丢掉缓存再取数。

0.4.10 移除默认持续输出的整对规格拒绝；`schedule` 继续通过 `clock.matches` 检查输出采样率，源身份/本地版本/队列/权限/各首解码规格不变。历史 temporary-trial 的异率限制保持。没有更改 PCM、重采样算法、音量、输出设备或原 UI。

实际 `prepare` 与 `schedule` 的隔离对照：同率不同位深、同率单/双声道候选从拒绝变为保留并预约；不同率候选保留但不预约；解码失败仍拒绝。没有冒充 Windows 声音验收。

## 排除原生音效后的音质

按用户要求不把 EQ、杜比、淡化、响度均衡或变速的差异算进本次比较。两端使用同一授权文件、固定版本 FLAC 解码器、整数 PCM 归一化和有界 PCM 模块，没有低档替代或有损再编码。上述核心解码模块与 `61f837f` 保真修正相同；最新 Windows `streaming.js` 只增加 acquisition 诊断字段。共享时钟后续增加用户调音量时的五毫秒平滑，固定增益和曲间排程不变。

新验证使用一份完整、已校验原生缓存 FLAC 的只读临时副本（16-bit、44.1 kHz、双声道）。Apple AVAudioFile 按源采样率生成独立参考；当前仓库 FLACDecoder 与 normalizeFlacPCM 解码得到 **20,477,960 个 float32 样本，差异数和最大差值均为零**。两份 PCM 还原为源整数后均匹配 FLAC STREAMINFO 内置 PCM MD5，避免两个解码器共同偏差被误当保真。[FLAC 原始 PCM 与校验定义](https://www.xiph.org/flac/features.html)。

当前 Mac 0.3.7 宿主中，独立资源实例走真实索引 Range 和 32 MiB PCM 缓存，在曲头、中段 100 秒、曲尾 230 秒各取一秒，与独立参考差异均为零。三段再经同采样率 OfflineAudioContext 的 BufferSource→Gain→destination：增益 1 输出逐样本一致；增益 0.5、0.73 与相应 float32 乘法结果一致。这里验证增益计算，没有证明原生 UI 的同一数值与原生引擎实际增益完全相等。只有离线节点，无可听节点，原曲 229.477451 秒暂停未变；原生缓存内容不变。此前三份真实 16/24-bit 文件、72,722,734 样本的验证仍见 [保真记录](AUDIO_FIDELITY_0.3.4.md)，本次没有把一份 16-bit 源说成新 Hi-Res 验收。

**这些证据证明已验证 FLAC 的原始音频样本在插件解码和同率 Web 渲染中保真；不能证明网易云原生引擎与 Web 最终设备输出逐位相同。** Apple 的独立解码参考不是网易云原生播放器的完整输出路径。Web Audio 暴露 float32 PCM；它能精确表示所支持 8/16/24-bit 的二进制归一化整数，不能把“使用浮点”直接当作降质原因。[Web Audio 样本格式](https://www.w3.org/TR/2021/REC-webaudio-20210617/#audio-sample-format)。

即使不使用任何音效，仍有两个未消除的比较条件：实际增益/舍入，以及输出到设备的重采样。本机重新查询到默认设备名义 **48 kHz**，当前文件/播放上下文为 **44.1 kHz**。Web 必须在输出阶段匹配设备采样率，原生路径也可能做转换，但转换算法/量化未做最终波形对照。[Web Audio 输出采样率规则](https://www.w3.org/TR/2021/REC-webaudio-20210617/#dom-audiocontext-audiocontext)。参数相同不自动证明内部算法相同；数值不完全一致也不等于已证明可听降质。

本轮没有修改设备采样率、用户音量或原生音效偏好，也没有原生/Web 声卡 A/B 或 Windows 回录。因此可确认“已验证原文件 PCM 无损保留，没有证据显示必然降质”，不能确认“所有歌曲、两种引擎、所有设备最终完全相同”。如需后一个结论，需要两端分别在同文件、同设备、相同实际增益下采集原生/Web 输出，时间对齐后检查残差；不能拿两端共有源码、系统音质标签或预约 0 帧替代。
