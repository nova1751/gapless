# Windows 持续 Web Audio 实施方案 v15

本方案对应macOS 0.2.4开发候选：首曲声音从Web直接开始；同采样率曲目持续使用一个Web Audio输出时钟，混合采样率边界重建输出；固定小包的只读可视化PCM与原动画共同读取声音输出时钟，驱动原有频谱和随节拍效果。不在每首尾部和开头反复切换后端。Windows尚无适配器、运行包或实机验收。Mac控制中心回跳仍未解决，不能照搬后宣布系统控制等价。

2026-11-15 原生路线补充：先验证 Windows 客户端独立预加载、同一输出持续及原管理器接认；能力通过则做原生薄适配，不必接入下文 Web 音乐核心。Mac 原生底层有条件复用输出，但现有宿主没有原生插件桥；不能据此推断 Windows 能力。见[纯原生入口与最小实施路线](NATIVE_GAPLESS_RECHECK_2026-11-15.md)。

## 推荐宿主与安装边界

Windows优先沿用[BetterNCM官方安装器](https://github.com/std-microblock/BetterNCM-Installer)和其[官方使用说明](https://github.com/std-microblock/chromatic/wiki/%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E)接入插件。安装器README给出了最低版本要求，但不能将最低版本理解为对所有新版3.x的兼容保证；实际客户端版本必须先验证宿主可加载、原生桥可用及能卸载恢复。

本仓Mac的`.plugin`不能直接用于Windows；当前推荐的是宿主及适配路线，没有Windows可运行插件。音源、控制、SMTC、可视化的数据订阅及开关恢复分别建立能力表。不要通过叠加多个SMTC或音频接管插件弥补所有权缺口，也不推荐主题插件来掩盖频谱失效。

## 1. 保留的职责

| 职责 | 所有者 |
|---|---|
| 登录、权限、试听限制、音质及缓存/下载偏好 | 网易云原有源选择流程 |
| 播放列表、随机顺序、前后切歌、歌词内容及窗口布局 | 网易云原有模型与组件 |
| 支持曲目的实际位置、听音时间、暂停、Seek、相邻曲目预约 | 共享 Web Audio 时钟 |
| 系统媒体状态和系统命令 | 验证后选定的唯一发布者/路由 |
| 原有频谱、随节拍视觉效果 | 原渲染器；实际播放后端提供只读PCM数据 |
| 关闭模式、不兼容和故障 | 恢复最新原生播放意图的事务 |

不增加主题、歌词面板、音质设置、EQ、混音或静音裁剪。开关复用宿主设置控件。保持原有授权音源和音质选择，不等于两种解码器、系统重采样和设备输出比特相同。

## 2. 先取得能力证据

固定 Windows、网易云、BetterNCM、Chromium 和设备的准确版本，逐项查实际调用、回调和语义。模块编号、命令、枚举、缓存目录不能复制 Mac 后直接使用。

| 能力 | 必须确认的行为 |
|---|---|
| 原有源选择器 | 不启动原生声音即可取得本次授权播放资料；遵守缓存、下载、音质偏好 |
| Load、Play、Pause、Seek、Stop、End | 参数、单位、错误、重复通知、回调订阅时机与实例标识 |
| 原生停声和恢复 | 输出停止后不会因系统命令重新出声；异常时恢复同曲、最新位置和意图 |
| 队列策略 | 当前行和可信下一行可确定；随机使用客户端已有顺序，不自行随机 |
| 歌词与原生窗口 | 可以消费适配器的状态/进度协议；桌面歌词和迷你窗分别检查 |
| 系统媒体控制 | 可可靠协调原生 SMTC 发布者和 Chromium；暂停/Seek 不出现第二个状态源 |
| 音效/倍速/特殊音源 | 能保留用户设置，或者有明确的不兼容原生路径；不得静默关闭 |
| 可视化音频输入 | 订阅/取消、数据类型、字节序、采样率、声道、包长度及PTS单位；确认是PCM还是FFT，以及分析长度是否保留最大容量，不能猜测 |
| 原动画时钟 | 查绘制接口的位置参数/时钟来源及原fps；Web显示数据和绘制位置须对应同一声音输出时钟，不能依赖低频UI进度刷新 |
| 缓存读取 | 元数据、内容身份、完整性、加密格式及取消可实查，不扫描整个磁盘 |

无法取得系统发布所有权时，不以周期纠偏、重复 Pause/Play 或第二个静音播放会话宣布完成。Mac 已有的回跳就是需要先解决的验收项。

## 3. 共享与平台适配边界

复用`shared/audio-resources.js`、`shared/playback-clock.js`和`shared/visual-pcm.js`。将`mac/player.js`的平台无关实例、控制代次、接认和恢复事务抽到共享协调器，Windows只绑定实查后的协议、视觉输入格式及能力；不要复制完整Mac文件维护两套竞态逻辑。

| 平台适配能力 | 输入/输出契约，不是已存在的 Windows API |
|---|---|
| 选择播放源 | 当前队列行及用户设置 → 原生授权 Load 资料 |
| 原生协议路由 | 原生命令 → 当前实例；适配器事件 → 原有 SDK/模型 |
| 队列查询 | 模式、列表、当前行 → 原有策略选定的下一行 |
| 缓存读取 | 已授权源与取消信号 → 校验后的字节流，或明确未命中 |
| 系统控制所有权 | 获取、发布快照、命令路由、恢复；都须有确认结果 |
| 原生恢复 | 源资料、位置、音量、最新播放意图 → 已确认恢复 |

每个异步结果复核账号、Load 代次、实例、控制代次、队列版本和时钟代次。旧任务完成不得切回旧歌、覆盖新 Seek 或改变最新暂停意图。

## 4. 持续播放流程

1. 新曲目由网易云原有选曲和授权流程取得 Load 资料。记录唯一队列行及完整恢复资料，再截获声音后端调用。
2. 优先复用同源已解码内存和完整磁盘缓存；否则读取该授权源。先准备、独立解码，禁止解码任务更改输出上下文。
3. 在唯一输出上下文播放；向原有 SDK 回报 Load/Play/Progress，保持原歌词和界面模型工作。装载期间只记录最新 Play/Pause/Seek 意图。
4. 用网易云原有队列策略取得下一行、选择其原有授权源、后台解码。源/缓冲/输出采样率相同才预约，不等JavaScript的End回调才播放；不同采样率保留预加载缓冲，进入正常End/Load边界。
5. 下一首在上一首 PCM 结束时刻开始。同一时钟先连续出声，随后通过原有 End/Load 流程更新曲目和歌词；本次 Native Load 再次核对授权、档位和源身份。
6. 接认后立即准备再下一首。不开第二条原生音乐输出，不在新曲目十秒后交还。
7. 没有可信下一首或准备失败时不错误预约。当前曲仍由 Web 播放；正常下一次选曲重新装载，不能把未预约边界记为无缝成功。

启动时已有原生音乐正在响仍需首次对齐接管；已确认暂停的曲目可以从保存位置直接 Web 继续。关闭模式、故障和原生设置不兼容仍需恢复，不能把这些交接说成没有延迟。

### 首曲入口与页面恢复

1. 在网易云播放桥建立时安装入口，早于第一次原生Load。开关关闭则不注入或立即放行；未知客户端和不兼容曲目仍由原生处理。
2. 原控制适配器未就绪时，暂存首个Load及其后相关Play/Pause/Seek/Stop/Unload，保留原始参数、序号和顺序。Mac为2.5秒、32条命令的初始化限额；Windows先测宿主加载时间，再设置明确上限，不能无限等待。
3. 适配器就绪后将队列交给共享控制核心，先准备同源缓存/授权源，再按真实源规格建立输出；不要启动时先创建固定44.1kHz上下文。资源准备沿用独立限额和取消机制。
4. 首次Web输出需要真实输入授权时保持当前Load等待；取消、换曲和关闭必须结束旧请求。不能仅因输入授权超时就先原生出声、随后自动追赶切Web。系统自动播放是否可直接启用，须实测宿主策略，不通过关闭浏览器安全策略实现。
5. 初始化超时放行同一原生请求，并将本次实例标为原生所有权；不能下一次心跳又自动切Web。下一次明确的新Load或重新开启模式再决定后端。
6. 页面恢复保存曲目、原始Native Load资料、位置、暂停意图和听音基数，复核账号、时效、实例及最新控制。支持且原生未出声时直接Web恢复；新鲜Load资料比旧快照权威。无SDK请求的恢复快照不能广播假的Load完成，也不能吞掉第一次手动Play。
7. 回退确认原生完成通知是否已注册。Mac SDK首次真实Load才注册onLoad；缺失时通过原有选曲流程建立通知，随后确认Load、Seek和最新暂停/播放意图。Windows核对自己的RPC与事件订阅顺序，不能假定RPC返回即整个加载完成。

验收分别覆盖完整进程冷启动、自动恢复/暂停恢复、真实第一次输入、初始化延迟与超时、等待授权时关闭/换曲、同采样率跨曲和原生回退。记录两条后端的命令和实际输出；没有原生Play命令是入口证据，不能替代设备回录。Mac目前有页面重载和受控协议延迟验证，完整进程冷启动尚未验收，见[0.2.4记录](STARTUP_WEB_0.2.4.md)。

## 5. 控制和系统状态

- Play/Pause：操作当前 Web 实例一次，发布实际意图。内部装载、Seek 和源节点替换不伪装成用户暂停。
- Seek：当前缓冲内在同一个渲染边界替换源节点；旧节点结束和新节点开始对齐，立即发布目标位置。暂停 Seek 保持暂停。快速拖动只保留最新目标，所有已接受 SDK 请求仍正确结束。
- 前后切歌：调用网易云原有队列动作，避免插件和原生各推进一次。旧曲目清理不得停止新实例。
- 系统控制：Seek/Play/Pause/前后切歌路由到当前实际音乐实例；状态快照来自同一个音乐时钟。先确认原生 SMTC 的开关能真正停止发布并注销命令处理器，再决定是否由 Chromium 发布。
- 如果必须保留原生系统发布：需要能将 Web 快照交给原生发布者，并使其系统命令进入适配器。不能仅让停住的原生播放器自行推算位置。
- 释放或回退：按确认后的所有权交接顺序恢复；禁止清掉另一发布者的控件。不能将 Mac 的静音载体及短时去重当作 Windows 的所有权协议。

Mac实际拖动记录确认前两次Seek后出现原生旧曲时长/播放率0，约546毫秒后恢复Web播放率1；不是Web音乐暂停。JS去重只减少音乐命令重复，不能阻止原生独立发布。Windows验收必须同时记录适配器快照、系统实际位置/播放率和命令时间，再与完全原生播放作对照。唯一所有权的具体要求见[系统所有权协议](SYSTEM_MEDIA_OWNERSHIP.md)；该协议尚非已存在的Mac/Windows接口。

## 6. 音源、缓存及格式

源身份至少包括账号范围、歌曲、请求/实际档位、可信内容指纹和规格。预加载在途任务与当前 Load 选中的源不同时，取得当前实际源；不得沿用旧结果或换低码率。

Windows 缓存读取先走客户端元数据及用户缓存目录。只读完整文件，核对内容 MD5、长度、档位和解码规格；解密、校验、读取有超时/取消，失败回到原授权源。不要假设 Windows 缓存与 Mac 格式相同。

当前共享资源管线完整解码 FLAC/MP3，插件预算 512 MiB、编码文件限额 128 MiB。Windows 必须先测实际 Chromium 解码支持；AAC、长曲、高采样率、加密下载和流式场景没有现成全覆盖实现。资源不足保持明确回退，不能无限加预算。

源按原采样率独立解码，输出AudioContext采样率必须与源/缓冲相同。同采样率保持一个时钟预约；混合采样率不允许放入旧上下文，旧音乐与预约节点停止后关闭旧输出，再按新采样率创建输出。异步关闭后复核时钟代次，避免旧Load关闭或接管新Load的输出；不支持该采样率时恢复同一授权原生源，禁止降档或强制改为44.1kHz。此边界可能有间隔，不宣称混合采样率也完全无缝。参考[Mac采样率保护](AUDIO_QUALITY_0.2.1.md)。

不要把所有曲目强制上采样到96/192kHz；这会增加无必要的转换与资源负担。设备格式与AudioContext不一致时系统仍可能重采样；Windows必须记录实际设备格式和共享/独占输出能力，不能承诺bit-perfect。保留原作品留白；处理编码器delay/padding必须有可信格式元数据并验证解码器是否已经处理，禁止用静音阈值裁剪音乐。

## 7. “其他效果一致”的实际边界

### 原有频谱与随节拍效果必须接回

Mac已确认原生`audioplayer.enableAudioData`／`onAudioData`订阅供原渲染器消费，Web接管后原生音乐停住，这条数据流也会失效。0.2.3从当前Web解码缓冲按实际输出位置只读采样，固定小包送入原渲染器，并使原绘制位置读取同一输出时钟；不改CSS、不启动第二路原生声音、不重写频谱动画。见[Mac包长度与时钟验证](VISUAL_TIMING_0.2.3.md)。

Windows按以下顺序适配：

1. 在原生播放下记录元数据和时间关系，确认视觉输入是PCM还是FFT。Mac的s16le/48kHz/双声道及毫秒PTS只适用于已查的Mac渲染器，不能直接当作Windows契约。
2. 保留原组件及渲染器。若同样消费PCM，复用只读采样器，传入Windows实查的`packetFrames`并按确认格式编码。核对真实分析调用的长度，不能让较短包夹带高水位容量中的旧尾部；rAF批次不可合并成变长大包。若消费FFT，适配确认的FFT格式，禁止把猜测音量或固定节拍作为分析结果。
3. 以实际输出位置而非未来渲染位置取样；原绘制的位置参数也须来自同一输出时钟，保留原fps和动画参数，不能使用低频UI进度作为动画时钟。Seek、Load、跨曲和控制代次变化丢弃旧视觉帧，新节点尚未到达输出时不得提前分析新位置。不得把上一首频谱送给下一首。
4. 只在视觉组件请求数据、页面可见且Web拥有播放时运行。暂停、关闭模式、组件取消订阅和原生恢复停止采样，放行原生视觉数据；不要永久改写SDK的订阅函数。
5. 可视化格式转换只能作用于显示副本。不能修改音乐AudioBuffer、音源档位、音乐上下文采样率或增益；限帧、限内存，异常隔离于音乐播放。后台停止、Seek和跨曲必须核对原图形是否跟随音乐。

原窗口及歌词布局不变，并不能证明所有后端能力相同。网易云私有音效、空间处理、响度、独占设备输出、倍速、试听、MV/电台和本地下载分别建立能力表。

当前 Mac 对不兼容设置恢复原生，因此并未实现“所有情况全 Web 且全部效果相同”。Windows 若要求这些情况也持续 Web，需要原生处理后的 PCM/等价接口并实查其时钟和授权；没有接口时不能猜测实现或声称等价。此方案不授权自行重写网易云音效或新增调音功能。

## 8. 分阶段验收

| 阶段 | 通过证据 |
|---|---|
| 协议与源选择 | 原有 SDK 普通控制、实际源/档位/缓存一致；未知版本安全回退 |
| 单曲 Web | 播放/暂停/暂停 Seek/快速 Seek/切歌/音量；窗口、歌词、迷你窗、桌面歌词正常 |
| 原有可视化 | 频谱/随节拍效果在Web播放、Seek和跨曲后变化正确；暂停、隐藏、取消订阅停止采样，回原生后原数据恢复；不增加音频节点或修改音乐缓冲 |
| 连续预约 | 同采样率自然A→B→C同一上下文；预约和实际输出回录，下一首超过十秒不交还 |
| 采样率保护 | 44.1→96→44.1kHz源/缓冲/上下文逐曲一致；活动节点不被后台解码关闭，异步切歌不采用旧时钟；不支持格式恢复原生 |
| 系统控制 | 跨曲后 Seek、前后切歌、暂停/继续；图标不自行闪动、位置不回跳、一次输入执行一次 |
| 模式与资源 | 列表/单曲循环、随机、队列编辑、缓存失效、账号/音质变化和内存上限 |
| 恢复与稳定性 | 关闭、刷新、睡眠、设备切换、网络失败、异步取消和长时间听音统计 |

预约零帧与回录没有新增断层只证明所测路径，不证明全部设备、蓝牙或 DAC 输出。任何阶段有未解决项就保留为开发候选，不将 Windows 方案描述成可运行发布包。

历史临时桥接方案保留在 [v10](WINDOWS_GAPLESS_IMPLEMENTATION.md)，不能用于当前持续 Web 模式。
