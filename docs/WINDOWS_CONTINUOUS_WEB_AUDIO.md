# Windows 持续 Web Audio 实施方案 v11

本方案对应 macOS 0.2.0 开发候选：开启无缝模式后，支持的音乐持续由一个 Web Audio 输出时钟播放；不在每首尾部和开头反复切换后端。Windows 尚无适配器、运行包或实机验收。Mac 控制中心回跳也尚未解决，不能照搬后宣布系统控制等价。

## 1. 保留的职责

| 职责 | 所有者 |
|---|---|
| 登录、权限、试听限制、音质及缓存/下载偏好 | 网易云原有源选择流程 |
| 播放列表、随机顺序、前后切歌、歌词内容及窗口布局 | 网易云原有模型与组件 |
| 支持曲目的实际位置、听音时间、暂停、Seek、相邻曲目预约 | 共享 Web Audio 时钟 |
| 系统媒体状态和系统命令 | 验证后选定的唯一发布者/路由 |
| 关闭模式、不兼容和故障 | 恢复最新原生播放意图的事务 |

不增加主题、歌词面板、音质设置、EQ、混音或静音裁剪。开关复用宿主设置控件。保持原有授权音源和音质选择，不等于两种解码器、系统重采样和设备输出比特相同。

## 2. 先取得能力证据

固定 Windows、网易云、BetterNCM、Chromium 和设备的准确版本，逐项查实际调用、回调和语义。模块编号、命令、枚举、缓存目录不能复制 Mac 后直接使用。

| 能力 | 必须确认的行为 |
|---|---|
| 原有源选择器 | 不启动原生声音即可取得本次授权播放资料；遵守缓存、下载、音质偏好 |
| Load、Play、Pause、Seek、Stop、End | 参数、单位、错误、重复通知、回调订阅时机与实例标识 |
| 原生停声和恢复 | 输出停止后不会因系统命令重新出声；异常时恢复同曲、最新位置和意图 |
| 队列策略 | 当前行和可信下一行可确定；随机使用客户端已有顺序，不自行随机 |
| 歌词与原生窗口 | 可以消费适配器的状态/进度协议；桌面歌词和迷你窗分别检查 |
| 系统媒体控制 | 可可靠协调原生 SMTC 发布者和 Chromium；暂停/Seek 不出现第二个状态源 |
| 音效/倍速/特殊音源 | 能保留用户设置，或者有明确的不兼容原生路径；不得静默关闭 |
| 缓存读取 | 元数据、内容身份、完整性、加密格式及取消可实查，不扫描整个磁盘 |

无法取得系统发布所有权时，不以周期纠偏、重复 Pause/Play 或第二个静音播放会话宣布完成。Mac 已有的回跳就是需要先解决的验收项。

## 3. 共享与平台适配边界

复用 `shared/audio-resources.js` 和 `shared/playback-clock.js`。将 `mac/player.js` 中平台无关的实例、控制代次、接认和恢复事务抽到共享协调器，Windows 只绑定实查后的协议和能力；不要复制完整 Mac 文件维护两套竞态逻辑。

| 平台适配能力 | 输入/输出契约，不是已存在的 Windows API |
|---|---|
| 选择播放源 | 当前队列行及用户设置 → 原生授权 Load 资料 |
| 原生协议路由 | 原生命令 → 当前实例；适配器事件 → 原有 SDK/模型 |
| 队列查询 | 模式、列表、当前行 → 原有策略选定的下一行 |
| 缓存读取 | 已授权源与取消信号 → 校验后的字节流，或明确未命中 |
| 系统控制所有权 | 获取、发布快照、命令路由、恢复；都须有确认结果 |
| 原生恢复 | 源资料、位置、音量、最新播放意图 → 已确认恢复 |

每个异步结果复核账号、Load 代次、实例、控制代次、队列版本和时钟代次。旧任务完成不得切回旧歌、覆盖新 Seek 或改变最新暂停意图。

## 4. 持续播放流程

1. 新曲目由网易云原有选曲和授权流程取得 Load 资料。记录唯一队列行及完整恢复资料，再截获声音后端调用。
2. 优先复用同源已解码内存和完整磁盘缓存；否则读取该授权源。先准备、独立解码，禁止解码任务更改输出上下文。
3. 在唯一输出上下文播放；向原有 SDK 回报 Load/Play/Progress，保持原歌词和界面模型工作。装载期间只记录最新 Play/Pause/Seek 意图。
4. 用网易云原有队列策略取得下一行、选择其原有授权源、后台解码。准备完成即预约，不等 JavaScript 的 End 回调才播放。
5. 下一首在上一首 PCM 结束时刻开始。同一时钟先连续出声，随后通过原有 End/Load 流程更新曲目和歌词；本次 Native Load 再次核对授权、档位和源身份。
6. 接认后立即准备再下一首。不开第二条原生音乐输出，不在新曲目十秒后交还。
7. 没有可信下一首或准备失败时不错误预约。当前曲仍由 Web 播放；正常下一次选曲重新装载，不能把未预约边界记为无缝成功。

启动时已有原生音乐正在响仍需首次对齐接管；已确认暂停的曲目可以从保存位置直接 Web 继续。关闭模式、故障和原生设置不兼容仍需恢复，不能把这些交接说成没有延迟。

## 5. 控制和系统状态

- Play/Pause：操作当前 Web 实例一次，发布实际意图。内部装载、Seek 和源节点替换不伪装成用户暂停。
- Seek：当前缓冲内在同一个渲染边界替换源节点；旧节点结束和新节点开始对齐，立即发布目标位置。暂停 Seek 保持暂停。快速拖动只保留最新目标，所有已接受 SDK 请求仍正确结束。
- 前后切歌：调用网易云原有队列动作，避免插件和原生各推进一次。旧曲目清理不得停止新实例。
- 系统控制：Seek/Play/Pause/前后切歌路由到当前实际音乐实例；状态快照来自同一个音乐时钟。先确认原生 SMTC 的开关能真正停止发布并注销命令处理器，再决定是否由 Chromium 发布。
- 如果必须保留原生系统发布：需要能将 Web 快照交给原生发布者，并使其系统命令进入适配器。不能仅让停住的原生播放器自行推算位置。
- 释放或回退：按确认后的所有权交接顺序恢复；禁止清掉另一发布者的控件。不能将 Mac 的静音载体及短时去重当作 Windows 的所有权协议。

Mac实际拖动记录确认前两次Seek后出现原生旧曲时长/播放率0，约546毫秒后恢复Web播放率1；不是Web音乐暂停。JS去重只减少音乐命令重复，不能阻止原生独立发布。Windows验收必须同时记录适配器快照、系统实际位置/播放率和命令时间，再与完全原生播放作对照。唯一所有权的具体要求见[系统所有权协议](SYSTEM_MEDIA_OWNERSHIP.md)；该协议尚非已存在的Mac/Windows接口。

## 6. 音源、缓存及格式

源身份至少包括账号范围、歌曲、请求/实际档位、可信内容指纹和规格。预加载在途任务与当前 Load 选中的源不同时，取得当前实际源；不得沿用旧结果或换低码率。

Windows 缓存读取先走客户端元数据及用户缓存目录。只读完整文件，核对内容 MD5、长度、档位和解码规格；解密、校验、读取有超时/取消，失败回到原授权源。不要假设 Windows 缓存与 Mac 格式相同。

当前共享资源管线完整解码 FLAC/MP3，插件预算 512 MiB、编码文件限额 128 MiB。Windows 必须先测实际 Chromium 解码支持；AAC、长曲、高采样率、加密下载和流式场景没有现成全覆盖实现。资源不足保持明确回退，不能无限加预算。

混合采样率使用同一输出上下文，源按原采样率独立解码，由 Web Audio 完成必要重采样。保留原作品留白；如果要处理编码器 delay/padding，必须有可信格式元数据并验证解码器是否已经处理，禁止用静音阈值裁剪音乐。

## 7. “其他效果一致”的实际边界

原窗口及歌词布局不变，并不能证明所有后端能力相同。网易云私有音效、空间处理、响度、独占设备输出、倍速、试听、MV/电台和本地下载分别建立能力表。

当前 Mac 对不兼容设置恢复原生，因此并未实现“所有情况全 Web 且全部效果相同”。Windows 若要求这些情况也持续 Web，需要原生处理后的 PCM/等价接口并实查其时钟和授权；没有接口时不能猜测实现或声称等价。此方案不授权自行重写网易云音效或新增调音功能。

## 8. 分阶段验收

| 阶段 | 通过证据 |
|---|---|
| 协议与源选择 | 原有 SDK 普通控制、实际源/档位/缓存一致；未知版本安全回退 |
| 单曲 Web | 播放/暂停/暂停 Seek/快速 Seek/切歌/音量；窗口、歌词、迷你窗、桌面歌词正常 |
| 连续预约 | 自然 A→B→C 同一上下文；预约和实际应用输出回录，下一首超过十秒不交还 |
| 系统控制 | 跨曲后 Seek、前后切歌、暂停/继续；图标不自行闪动、位置不回跳、一次输入执行一次 |
| 模式与资源 | 列表/单曲循环、随机、队列编辑、缓存失效、账号/音质变化和内存上限 |
| 恢复与稳定性 | 关闭、刷新、睡眠、设备切换、网络失败、异步取消和长时间听音统计 |

预约零帧与回录没有新增断层只证明所测路径，不证明全部设备、蓝牙或 DAC 输出。任何阶段有未解决项就保留为开发候选，不将 Windows 方案描述成可运行发布包。

历史临时桥接方案保留在 [v10](WINDOWS_GAPLESS_IMPLEMENTATION.md)，不能用于当前持续 Web 模式。
