# 临时 Web Audio 桥接并交还原生（0.1.11）

已实现并安装：普通播放由网易云原生后端出声；Web Audio 只覆盖 A 的尾部与 B 的开头，随后交还原生。0.1.8 持续接管整首的行为已收窄。

0.1.10 在资源准备阶段增加 [网易云完整缓存优先读取](CACHE_PRIORITY.md)。0.1.11 已激活，并用完整原生缓存完成 A→B→原生 B 的实际协议复验；Web 预加载音频下载为零，交还后节点与上下文退出。0.1.9 的数据保留为历史协议场景。原生累计计时只提供粗粒度进度：运行中 Seek 不建立精确计时锚点，进入桥接时仍依赖原生进度估算；不能将该门槛解读为设备输出的采样级对齐。

0.1.11 源码补充接管失败/取消后关闭预热上下文，关闭期间阻止重复接管；无手势时等待真实输入后再重试。已在实机确认主动 Seek 取消及一次注入预热失败后资源释放，见 [本轮检查](IMPLEMENTATION_CHECK_0.1.11.md)。

## 10 秒是窗口，不是固定切换位置

```text
原生 A ── 接近结尾 10 秒 ── Web A 尾部 → Web B 开头 ── 原生 B
           准备、对齐、切换        同一音频时钟预约        准备、对齐、切换
```

后台可以提前下载、解码当前及可信下一首，但不能因此接管当前整首。进入条件为距结束不超过约 10 秒、两首完整准备、来源与规格匹配、原生 Seek 已稳定、播放意图未改变。B 的实际输出进度达到约 10 秒时提交交还；用户拖进度或暂停时提前交还。准备与握手有耗时，因此实际退出可略晚于 10 秒。

A→B 的预约发生在同一个 AudioContext 内，下一首从上一首缓冲的结束时刻开始。B 不再预约 C，也不在 Web 后端连续播放整条队列；交还原生以后，下一次符合条件的曲尾才能重新桥接。

## 双向对齐

**原生 → Web：** 原生保持出声，先预热 Web 设备输出。通过原生 Load/Seek 位置与累计播放计时建立位置锚点；静默准备 Web 音频，补偿 `currentTime` 与 `getOutputTimestamp()` 的渲染/设备输出时差。重新测量偏差，通过门槛后，在预计的设备输出时刻打开 Web 音乐输出并暂停原生。校准不通过就取消静默节点，保持原生。

**Web → 原生：** B 接认后即用网易云提供的同一音源资料装载原生 B，保持暂停；这不会停止 Web。到交还窗口后，暂时关闭原生输出，Seek 到 Web 当前实际输出位置，启动并核对新进度通知与累计计时是否推进。由于原生进度通知实测有明显滞后，原生累计计时也实测按约 2048 帧更新（44.1 kHz 时约 46.44 ms），不能把单次读数当连续播放时钟。交还时用约 200 ms 的短窗口、约 8 ms 间隔采样定位计时块边缘并插值，检查计时稳定及持续推进，再用确认的 Seek 位置与时间差校准；初始启动补偿约 40 ms，后续按实测误差修正。Native 累计计时不是设备采样时戳；通过估算门槛后才恢复原生输出，并在对应的 Web 输出时刻关闭 Web 音乐，释放音频节点及播放上下文。

正常切换的估算计时偏差门槛为 25 ms，最多三次原生端校准。原生端静默准备有 3 秒超时保护；无法完成时显式恢复原生，不能把临时桥接延长成整首 Web 播放。异常恢复仍可能有间隔，不把它描述成无缝成功。

## 原生输出选择与取消

原生预热时使用已验证的 `audioplayer.setVolume` 关闭它的声音输出；用户音量另行保留并恢复。它只用于防止两路同时出声，不改变用户音量选择，不加入 EQ、交叉淡化或静音裁剪。内部音量通知不写入网易云界面；准备期间用户调音量仍会立即作用于正在出声的 Web，随后恢复最新值。成功、取消、超时、页面退出和确认失败路径均有恢复处理，并保留仅含音量的本地恢复标记以覆盖页面异常退出。

暂停/Seek/Load 都使旧控制代次失效。拖进度先按用户位置响应，再重新对齐并交还；暂停先停止实际声音，再把原生定位到暂停位置。手动选另一首时取消旧节点与旧事务，按网易云流程播放新曲。旧异步完成不能操作新曲目。

原生候选的内部 `onLoad` 被隔离，防止已接认的 SDK 再次自动播放。音源授权、用户音质、当前实际档位、队列、音量、播放速度、歌词与窗口样式继续按原有规则；资源不兼容时保持原生，不换低音质源。普通原生阶段仍可能保留当前/下一首的解码缓存，受 512 MiB 管理预算约束；交还后 Web 音乐节点和播放上下文退出。

## 系统媒体控制的实际边界

音乐已交还原生，但 0.1.8 的静音系统媒体载体仍在页面生命周期内保留，用于跨后端同步控制。此前已实测直接释放 Chromium 会话会禁用共享的系统上一首/下一首/Seek 命令，不能为了“全原生”直接清理它并重新引入控件失效。

原生 NowPlaying 更新绕过页面桥，当前还没有可验证的接口隔离它。因此本版不宣称已经实现单一原生系统状态发布者，也不宣称控制中心图标闪动、原生自身的进度回跳已全部解决。交还后音乐出声后端是原生；保留的载体没有音乐数据。

## 验证与限制

本机 SDK 的 `preLoad` 与 `getPlaybackInfo` 仍为空实现；本版使用已验证的 Load、pause、Seek、play、累计计时和音量接口，而没有盲调隐藏原生无缝开关。Windows 必须独立验证对应能力，不能直接使用 Mac 协议。

当前验证见 [mac-runtime-0.1.11.json](verification/mac-runtime-0.1.11.json)，历史协议见 [0.1.9 记录](verification/mac-temporary-bridge-0.1.9.json)。已观察到指定歌曲实际预约跨曲与交还原生，另外验证桥接开头的拖进度、暂停/继续和交还后的原生控制。未新增测试用例，未执行应用构建或全量静态检查。

**计时校准不是设备输出的采样级证明。** Web 有设备输出时间戳，原生只提供播放计时与进度事件，原生解码器、设备缓冲与系统调度仍可能带来偏差。未回录声卡或数字输出，不能承诺所有设备都绝对无断音、无重音或无点击声；保留音源自身留白，且不承诺两种输出后端比特完全相同。
