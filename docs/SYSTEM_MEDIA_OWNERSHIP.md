# 持续 Web 播放的系统状态所有权

当前问题仍未解决。0.2.0 已让支持的音乐持续由 Web Audio 播放；这能消除每首反复交接音乐输出，但不会自动移除网易云原生系统媒体处理器。不能把声音连续等同于系统控件完全一致。

## 实机证据

2026-11-15，网易云3.1.12（3444）、macOS26.6.2 arm64：用户实际点击后从控制中心拖动三次，Web位置发布和系统MediaRemote状态同时只读采样。

| 拖动目标 | Web发布 | 系统随后收到 | 恢复Web状态前的错误状态持续时间 |
|---|---|---|---|
| 76.609302秒 | 目标位置，实际曲时长234.923877秒，播放中 | 原生旧曲时长242.52秒，播放率0 | 547.45毫秒 |
| 186.764685秒 | 目标位置，实际曲时长234.923877秒，播放中 | 原生旧曲时长242.52秒，播放率0 | 545.45毫秒 |
| 187.88816秒 | 目标位置，播放中 | 采样区间未出现上述错误状态 | 未复现 |

音乐节点在同一渲染边界替换，期间没有Web暂停通知。第二发布者上报暂停能解释按钮闪动；记录没有屏幕录像，不能认定所有可视回跳来自同一原因。历史完全原生对照也有回跳。脱敏记录见[系统Seek证据](verification/mac-system-seek-0.2.0.json)。

只读原生协议检查确认：系统Seek直接进入原生`setCurrentTime:`，之后延迟更新系统信息；`reloadNowPlayingCenter`读取原生`currentTime/currentStatus`。JS命令包装和旧事件过滤不会拦住这个进程内路径。Chromium关闭远程命令时只执行`removeTarget:self`，不移除网易云target，且会禁用共享命令；反复释放、重建Web会话不能可靠解决所有权。

已查接口的限制：Mac SDK的SMTC开关没有原生调用；旧`setCurrentPlay`不更新系统时钟，`setCurrentTime`实际Seek原生声音后端；`removeAll`清除迷你窗列表，`stop`重置窗口信息，均不是发布者注销接口。实机释放原生音频实例仍复现回跳。BetterNCM-mac宿主在`plugins.mjs`明确忽略`native_plugin`，注册原生API列表为空；目前没有可调用的进程内所有权桥。

## 最小修复边界

推荐保留网易云原有系统发布者，在无缝模式中改由它消费Web真实快照，而不是让停住的原生声音后端发布自身状态。需要宿主提供**进程内**适配能力；下面是需要实现的契约，不是当前已经存在的API。

1. 接管成功后，在原生主队列切换实际播放所有者。停止原生声音后端驱动NowPlaying的通知和延迟任务；保留原曲目信息、系统控件及窗口组件。不能只静音原生声音。
2. 原生唯一发布者接收Web快照：曲目实例、控制代次、实际输出位置、时长、播放意图和时间锚点。旧曲、旧Seek、旧所有者任务不得再更新系统信息。状态更新和命令路由使用同一所有者代次。
3. 原系统Seek/Play/Pause路由至Web当前实例，禁止同时Seek停住的原生后端。前后切歌仍调用网易云原有队列动作，一次输入只推进一次。内部装载和节点替换不发布用户暂停。
4. 控制中心、原生迷你窗、桌面歌词分别消费当前所有者的进度；保留组件与样式，不能用启动第二条音乐输出来让旧时钟追赶。
5. 关闭模式或故障时，先按最新位置/意图确认原生恢复，再切回原生所有者；取消旧Web命令和发布任务。插件失联必须能恢复原生，且不得清掉其他应用的系统媒体控件。

这条路线不需要重写歌词界面或音源选择。Web仍负责解码和连续音乐时钟；原生桥仅协调已有系统状态与控制依赖。需要宿主/客户端支持后才能实现并验收，不能用独立进程的第二个发布者代替，也未通过修改签名、关闭系统保护或运行中注入来绕过该限制。

## Windows对应要求

先实查网易云Windows的SMTC开关是否真的停用状态发布和命令处理。若可可靠释放，才能让Web成为唯一发布者；若不可释放，同样需要原生SMTC消费Web快照并路由命令。模块编号、接口名、参数和缓存格式需分别核对，不能复制Mac内存地址。

验收同时观察真实声音、系统位置/播放率和SDK控制完成：自然跨曲后拖进度、快速连续拖动、暂停/继续、上一首/下一首，以及关闭和失败恢复。当前Windows只有[实施方案](WINDOWS_CONTINUOUS_WEB_AUDIO.md)，没有运行包；当前Mac也未通过系统所有权验收。
