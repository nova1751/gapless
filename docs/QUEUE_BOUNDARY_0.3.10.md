# 曲尾预约与降级检查：Mac 0.3.10

基于 main 8867cbb。用户报告偶发曲尾切回原生，本次未捕获该次故障日志，不能认定唯一原因。源码确认一条过于严格的路径：整个队列签名变化即撤销已预约节点；若处于接认阶段还直接触发 `queue-during-claim` 回退。无关队列项元数据变化也可能命中，曲尾不足 80 ms 时无法重新预约。

## 修正

- 队列更新后重新计算实际下一首；同一队列项、账号、源规格、时钟代次及预约边界仍匹配时保留已排程节点，更新其队列代次。真实下一首变化仍取消。
- 接认阶段保留原曲的最小选曲资料，按新队列重新计算「原曲→下一首」；仍是同一项且输出有效才继续接认。原生 Load 的权限、档位和文件指纹核验保持严格。
- `gaplessMac.status().lastFallback` 保留页面内最近一次切回原生的原因、位置、曲目及源采样率，避免高频缓冲日志把原因挤出。记录内存有界，重载后清空；主动关闭也会记录为 `disabled`。

真实缓存／解码失败、流式欠载、输出上下文挂起、源或权限变化、接认超过三秒仍可回原生。异采样率也不保证连续。没有取消安全回退、增加混音／淡化或改音源质量。

## 本轮证据

安装前 0.3.9 两次 Baptized In Fear → Open Hearts 自然跨曲均成功，接认约 179／280 ms。安装 0.3.10 后，重载恢复 Open Hearts 的播放意图，观察到 Open Hearts → Moth To A Flame 自然跨曲，预约零帧间隔、接认约 319 ms，随后下一首继续预约，未回原生。接认耗时不代表声音间隔；本轮没有音频回录或听感量化。

无关队列更新和接认期间更新的修正已代码审查，未实机注入；尝试界面拖动未改变队列，不能算作该分支验收。跨曲后界面工具报告没有可读窗口，系统控制、歌词和频谱未重新逐项验证。没有新增测试用例、全量静态检查或应用构建。包与安装／运行文件校验见 [机器记录](verification/mac-queue-boundary-0.3.10.json)。旧 0.3.9 包保留回退。

## Windows 对应建议

Windows 0.4.14 以 `sameEnvironment` 的完整队列快照判断候选和当前播放有效性，也有无关队列更新触发 `environment-changed` 的可能。本轮不改 Windows 源码或安装。

建议分开检查账号、授权源／档位、输出设备、有效播放模式与真正相邻的唯一队列项。只有无关行变化时，可以保留已有预约；接认阶段从原曲重新解析下一首并检查同一项，不能仅凭曲目 ID 放宽整个环境校验。保留原生 Load 的文件身份核验、代次屏障、重复 ID／未知下一首回退以及输出故障回退。增加有界最近回退原因，并分别实机检查无关行更新、真正下一首改变、接认中更新和缺数据情况；Mac 记录不能替代这些 Windows 验证。
