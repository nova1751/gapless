# 0.1.7：系统媒体同步与 Seek

网易云 3.1.12（3444），BetterNCM-mac 0.1.7。新包已安装，无缝开关保持启用。目标是让原生界面和 macOS 系统卡片跟随实际播放，不为修图标重启原生音乐流。

## 实现与确认

- 接管期间使用 Media Session 发布当前曲名、封面、播放／暂停状态和真实音乐时钟。约 128 KiB 的全零 HTMLAudio 载体只建立系统会话，音乐继续经过原有 Web Audio 节点，不改变音源、音质选择、音量、采样率或界面 CSS。[Media Session 标准](https://www.w3.org/TR/mediasession/)
- 普通播放、暂停、前后切歌保留网易云原生命令处理；Media Session 不再发第二次传输操作。用户确认曲名、按钮与实际声音一致。控制中心已通过 AX 读取正确曲名、暂停按钮及滑块。
- 首版只观察系统 Seek，未转给实际音乐所有者，用户发现声音进度不一致。已补齐现有 SDK Seek 路由，合并 80 ms 内相差小于 20 ms 的同曲目重复目标，串行等待 SDK 完成；后续目标只保留最新一次。暂停时拖动不启动音乐，播放中复用原有同一时刻替换节点的路径。
- 用户复测确认声音跟随系统拖动目标。日志记录四次系统 Seek 完成，无 Seek、系统同步或桥错误。记录中 Redux `playingState = 2` 对应实际暂停按钮可见，不能与原生 SDK 事件值混用。
- 首次接管在输出预热后直接于当前音频时钟起播，移除原有固定 10 ms 延后。跨曲预约仍使用同一时钟，不等待界面接认；已有实际跨曲及 Seek 观察保持音频上下文运行。尚未设备回录，不能称首次交接绝对无卡顿。
- 同步失败只释放辅助会话；无缝音乐继续。原生恢复、Load、停止、卸载时先释放会话，再由原生正常发布状态。记录包含实际回到原生播放、辅助会话释放的场景。

## 未解决的系统按钮闪烁

用户确认系统拖动时声音正常，但卡片按钮会短暂从暂停切到播放再恢复。它是显示状态问题，未观察到对应声音暂停，不能标为完全修复。

已核对原生系统 Seek 直接调用播放管理器 `setCurrentTime:`，不经过插件的 JS 命令拦截；原生 Now Playing 更新又依据原生 streamer 状态。最可能仍有原生与 Chromium 的状态写入交叉，现有 JS 过滤只能保护前端事件，不能禁止原生系统处理器。短时原生状态观察不足以确认所有内部写入的时序，所以不把这一推断当作完整故障证明。

要保证拖动期间按钮完全稳定，需要在原生桥协调系统 Seek 的所有者与 Now Playing 状态写入。当前已检查 SDK 没有可用的独立状态发布或系统 Seek 门控接口；不能靠重复赋值相同 JS 状态证明原生写入已被阻止。保留最小有效同步和音频 Seek 修正，不重新引入反复暂停／恢复或旧版纠偏计时器，也不关闭整个无缝功能。

原生对照已有的进度回跳仍单独记录；资源、格式、权限和未知队列的回退也保留，没有以降低音质扩大无缝覆盖范围。
