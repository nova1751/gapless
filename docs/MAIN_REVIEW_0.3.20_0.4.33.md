# 最新 main 复核与 Mac 安装（0.3.20 / Windows 源码 0.4.33）

2026-11-27，快进同步远程 main `923e1b7`。该提交已包含 Mac 0.3.19、Windows 0.4.32 的流式预读、解码器复用、4 首暖缓冲、并行输出预热、Seek 期间旧进度抑制等优化。本轮保留这些改动，在 Mac 修正保护遗漏并安装完整新版；不复制 Windows 独有的 DLL、选曲归档或控件选择器。

## 复核修正

- Mac 保留可随更新加载的管理入口，但实际接管仍限已验证的 3.1.12 原生协议。仅接口名称／函数特征相似，不能证明其他 Mac 客户端的缓存格式、通知协议和输出门控兼容；未知版本保持原生。
- 完整有效索引与 `.uc!` 后缀不作为文件不可变证明。恢复读取前后文件版本检查，原生替换或改写缓存时拒绝结果并复用已有一次重查；保留缓存根目录优先、64 个挂载上限及快速 XOR。
- 原生缓存辅助实例 Stop 失败后，不能仅凭重新打开开关清掉故障。只在任务和清缓存屏障均结束后重置可恢复的清缓存超时；未确认停止的通道保持封闭，需要重新初始化。
- 拉数剩余预算不足 250 ms 时直接报告超时，不再为了满足下限发起注定超过本次读取期限的新任务。已发起任务仍执行原有 Stop 清理。
- 旧加载异常会先取消该旧实例自己的区间读取；只有仍拥有同一实例／代次时才结束全局缓冲通知或进入原生恢复。并行预热失败后，尚未结束的门控分支不会继续新建缓冲准备，也不会覆盖更新的切歌／Seek。
- 两端共用的 Range 接收保留 2 MiB 请求上限和 32 位 XOR，恢复接收过程中的长度上限。异常服务器返回超长数据时立即取消，不能先用 `arrayBuffer()` 收完整个响应再发现超限。Windows 源码因此更新为 0.4.33；本轮没有 Windows 安装包或实机验证，其上游安装／运行证据仍为 0.4.32。

音源授权、请求音质、PCM 归一化、声道、音量曲线、采样率与预约时钟算法均未改变；没有新增歌词／频谱样式、淡入淡出、静音裁剪或永久歌曲缓存。不同采样率仍重建输出，不能承诺所有边界零间隔。

生产方法定向诊断确认：停止未确认的故障保留、清理仍在运行时不能重置、已结束清理的清缓存超时可重置；Range XOR 后字节一致，超长响应被拒绝。这些诊断不替代客户端声音或系统控制验收。
