# Windows 0.2.9：仅主界面入口及前后切歌缓存

上游复查 origin/main=f6a4b72，已与工作区基线一致。平台实现不等同。

## 修复

- 菜单只挂载主界面 MiniModeIconBar；不再注入歌词详情页的 right.draggable。
- 手动切歌 Stop/Load 不再先丢弃所有已准备资源和关闭输出。短暂保留以接住下一次 Load；没有后续请求时 2.5 秒释放。停止当前/预约节点，保留原生音量恢复与控制代次。
- 单独保留最近播放的一首解码缓冲，单项最多 128 MiB，计入共享 512 MiB 预算。下一次同账户、同请求档位且身份匹配的 Load 可复用；内存压力时先释放这个可选缓冲再重试。关闭、回退和闲置清理释放它。
- 来源、身份、完整性、档位、采样率校验未降低；混合采样率仍由原时钟按规格切换，不承诺无缝。

## 实查

- 更改前 Windows abandon 在 Stop 和 Load 时清空资源、关闭时钟；Mac Load 会先 lookup 并保留匹配资源。Windows 之前即使下一首已预加载也重做读取/校验/解码。
- 仅修复清空后，Baptized In Fear 首次装载 1989ms，Open Hearts 内存复用 99ms；返回上一首等待 5 秒仍在加载，证实上一首缓冲已释放。
- 最终包：首次装载 2456ms；切 Open Hearts 为 30ms；返回 Baptized In Fear 为 35ms。后二者 memoryHit=true，contextGeneration 始终为 1。三次源/解码/输出均 44100Hz。
- 上述为经原客户端 select 工作流的协议检查，计时从插件 Load 开始到 Web 就绪，未计入授权解析，也没有本轮设备输出回录，不能宣称实际断音 30/35ms。
- 运行页面主入口=1，歌词页入口=0。关闭后 handingBack 能报告真实恢复事务，随后 owns/nativeMuted=false，activeNodes=0，资源 held/reserved/pending 全0。
- 最终保持开启、暂停。增量语法及 ZIP 打包通过；未新增测试文件或运行全量构建。

## 与 Mac 的边界

同源缓存优先、首曲直接 Web、同采样率单时钟及异常原生恢复思路一致。Windows 桥、缓存格式、视觉回调不同。Mac 的等待首次输入授权、页面恢复快照、系统媒体所有权处理不能说已全部移植。此次保留上一首缓冲是 Windows 针对实测问题的局部优化。强杀进程后开关持久化仍沿用 0.2.8 已记录的未解决边界。
