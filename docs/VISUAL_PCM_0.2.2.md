# 0.2.2：恢复原有频谱和随节拍动态

本页为0.2.2历史记录。用户随后发现动画节奏异常；变长包与原组件高水位分析长度不兼容、绘制时钟不同步已在[0.2.3修正](VISUAL_TIMING_0.2.3.md)，不应沿用本页的变长包策略。

用户实测Web接管后频谱／随节拍效果失效。原因是界面虽仍收到播放进度，原渲染器的PCM输入来自停住的原生音频后端；进度并不能替代音频分析数据。本版只补回这份输入，保留原动画、资源、布局和歌词组件。

## 实查接口

Mac 3.1.12的SDK通过`setAudioDataEnableState`调用`audioplayer.enableAudioData`，`subscribeAudioData`订阅`audioplayer.onAudioData`，把十六进制字节串还原为数值数组。原效果组件将字节复制进其WASM内存并调用`_AESetAudioData(ptr, pts, byteLength)`。

短时原生播放收到1600字节数据包及约51535毫秒的PTS；同一原生处理块的若干数据包可能共享PTS。已读取当前加载的原厂WASM：该入口第三参数按4字节计算一帧，并用48000计算持续时间，第二参数除1000后传递播放位置。浮点入口会先转换成16位样本；与原生数据的s16le统计共同确认现有视觉输入为48kHz、双声道、16位小端PCM。这个契约只适用于本次实查版本，不能复制成Windows默认值。

## 实现边界

- 共享采样器从当前音乐AudioBuffer的声道数组只读取值，按`getOutputTimestamp`对应的实际输出位置产生视觉帧。Seek、Load、控制或时钟代次变化立即丢弃旧帧。
- 显示副本按原渲染器的格式转换，再通过原SDK回调交给原效果组件；没有新CSS或新的频谱渲染器。转换仅用于视觉分析，不写入音乐缓冲、不创建AudioContext或音乐节点、不改播放采样率及音量。
- 只在原组件启用数据、页面可见并由Web播放时使用requestAnimationFrame。单帧最多50毫秒、字节缓冲9600字节；长时间停顿跳过旧视觉数据，不积压。
- 暂停、原生恢复、关闭插件或页面退出停止采样；Web拥有播放时抑制停住原生实例的旧PCM回调。原生恢复后原PCM自动放行，原订阅/取消函数和enable命令保持原样。
- 可视化错误只停止这条显示支路，不触发音乐暂停或原生恢复。显示副本采用线性插值和16位量化，并非所有视觉分析结果与原生逐值等价的证明；它不参与听到的音乐。

## 已完成的实机核对

完整0.2.2包已安装、注册并重载。The Hills原环形频谱在Web播放下恢复变化，源/解码/音乐上下文仍为44.1kHz；原歌词、布局和动画资源保持。Seek70后视觉位置跟随新的输出位置；暂停后计数稳定且无采样任务，继续后恢复。

随后Seek到曲尾并完成The Hills→I Was Never There实际预约跨曲，原曲名、歌词、封面和环形频谱更新；输出时钟代次2保持，预约间隔0帧。当前曲视觉位置在1.43794秒，播放器渲染位置1.50408秒，差值包含输出管线延迟，不以未来渲染位置提前驱动。

原生恢复后Web采样任务停止，250毫秒内收到16次原生PCM回调。验证完成后恢复原曲The Hills、暂停于51.49秒，插件保持开启。累计7964视觉帧平均同步处理0.744毫秒、最大5.2毫秒；这是短时JS耗时，不是所有设备的CPU、不卡顿或音质证明。

没有新增测试、全量静态检查或应用构建；已做增量JS语法、包CRC、源/安装/运行文件SHA和上述实机核对。详情见[记录](verification/mac-visual-pcm-0.2.2.json)。未穷举全部特效资源、多声道、高采样率、页面隐藏/恢复及长时间性能；系统控制中心回跳仍未解决。Windows只更新[实施方案v13](WINDOWS_CONTINUOUS_WEB_AUDIO.md)，没有Windows运行包。
