# Mac 0.3.4 / Windows 0.4.6：PCM 保真与原生音效保护

2026-11-16，基于 main `8a638aa`。Mac 0.3.4 已打包安装；Windows 共享代码已更新，新候选未在 Windows 安装或复测。这里区分源文件、解码样本、Web 渲染和设备输出，不用音质标签代替音频证据。

## 发现与修复

网易云 Mac 3.1.12 设置模型的默认值为 `playFade: true`，用户保存的值也为 true。默认勾选不能证明原生实际声音包络：这个客户端的 `AudioPlayer.switchEffect` SDK 方法只返回成功，没有发送后端命令。本版按保存的用户偏好保守处理，不以这个空接口认定能复现淡入淡出。

Mac 现在与 Windows 一样：淡入淡出、杜比，以及已识别的音效、音量均衡、空间音频、变速需要原生处理时，不用 Web 输出忽略它们。两端补上 `systemAudioEnhance` 保护。未修改音质、音效或淡入淡出的用户设置。**保留淡入淡出开启时会使用原生，不能同时宣布无缝开启即有连续 Web 输出；使用无缝需在网易云原设置中关闭该冲突项。** 诊断新增阻断原因、源位深和声道数。

旧 FLAC 转换先恢复整数，再按正负两个比例匹配 Chromium 完整解码；这不是整数 PCM 的统一满量程比例。对三个已校验源，与 Apple AVAudioFile 同采样率解码相比，正向样本存在数值差异，最多一个整数最低有效位。原来“与 Chromium 相同”的证据不能推出“与源 PCM 相同”，更不能推出与网易云原生输出相同。

已改为 `round(wrapperPCM * (2^(bits-1)-1)) / 2^(bits-1)`：从 WASM 包装器恢复有符号整数，再按统一二进制满量程转换。8/16/24-bit 的归一化整数可由 float32 精确表示。顺序和索引 Seek 共用 `normalizeFlacPCM`，消除重复转换逻辑。32-bit FLAC 仍回原生，没有偷偷降位深；音量、采样率、缓存和播放时钟策略未重写。

## 实测

输入是原生缓存的只读隔离副本，XOR 解密后的文件 MD5 与源身份匹配；另一个副本未通过完整哈希，未作为保真样本。没有下载替代音源或写原生缓存。参考由 Apple AVAudioFile 在源采样率解码为 float32；把参考还原为小端 16/24-bit 整数后，整曲 MD5 与 FLAC STREAMINFO 内置 PCM MD5 相同，证明参考保留了这三个文件的原始整数样本。

| 源 | 规格 | 检查样本数 | 旧转换最大整数差值 | 修正后 float32 差异数 / 最大差值 |
|---|---|---:|---:|---|
| 2670863319 | 16-bit / 44.1 kHz / 双声道 | 20,477,960 | 1 | 0 / 0 |
| 29027690 | 24-bit / 48 kHz / 双声道 | 23,128,358 | 1 | 0 / 0 |
| 1378406132 | 24-bit / 44.1 kHz / 双声道 | 29,116,416 | 1 | 0 / 0 |

共 **72,722,734** 样本。比对运行在实际安装的 `GaplessStreamingResources`，用隔离输入读完整已验证文件；没有可听节点，不改当前播放器时钟。旧转换的差异信噪比约 93.29 dB（16-bit）及 141.44–141.65 dB（24-bit）；数值差异不等于已证明可听降质，未做盲听评价。

实际安装的索引与 32 MiB PCM 分块链路：每个文件在 0、100 秒和曲尾各比对一秒，共九处，逐样本差异及最大差值均为零。三个真实片段通过同采样率 `AudioBufferSourceNode → Gain(1) → OfflineAudioContext` 渲染也没有差异。24-bit 整数构造的 44.1/48/96/192 kHz 离线渲染分别比对 8,192 个样本，无差异；96/192 kHz 是构造 PCM，不能当作真实 Hi-Res FLAC 验收。

8/16/24-bit 全有符号整数范围共 16,843,008 个值，WASM 包装比例的 float32 输入经新转换后与原整数归一化值完全相同。临时数值检查不是新增仓库测试用例。原始音乐、参考 PCM、播放资料和临时检查脚本不入库。

## 结论与边界

对上述受支持 FLAC，已经证明插件解码、分块读取和同采样率单位音量的 Web 离线渲染没有减少原始 PCM 的精度；没有有损再编码、低档替代或插件内跨采样率转换。旧归一化差异已消除。

这不是网易云原生引擎完整输出或 DAC/蓝牙的逐位等价证据。CoreAudio 查询到当前默认输出设备名义采样率为 48 kHz；44.1 kHz 上下文与设备不同率时，Web 输出仍要重采样，[Web Audio 规范](https://www.w3.org/TR/webaudio/#AudioContextOptions)明确了该处理。原生也可能重采样，但未比较两条最终设备链路的算法、音量量化及输出。不是发现了必然可听降低，也不能宣称最终比特直通。

不同采样率继续重建输出，允许间隔；本版没有为保真自动修改系统设备采样率。没有重做 0.3.4 的设备回录或完整播放矩阵。正常重启后，临时关闭淡入淡出以验证真实 Web 播放：Baptized In Fear 首曲装载 331 ms，自然跨至 Open Hearts，预约 0 帧、接认 173.4 ms；跨曲后暂停及 Seek 到 117 秒正常。重新开启淡入淡出后，回原生保持暂停和 117 秒，工作内存归零。杜比/音频增强的暂停状态标记检查和恢复通过，音质偏好未变。原曲 Call of Silence、160.9838 秒暂停、374 首队列、原淡入淡出 true 和 Hi-Res 偏好已恢复，实际播放页样式正常。这些是控制、显示和协议证据，不是新增设备声学结论。

验证期间一次原生队列恢复请求未完成、随后出现空白画面，正常重启后恢复；后续沿原队列动作完成上述控制及最终原曲/界面检查。没有证明该临时异常的根因，也不将其隐藏为全程无问题。
