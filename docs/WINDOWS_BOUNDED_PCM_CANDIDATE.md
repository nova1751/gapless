# Windows 原生数据源的有界 PCM 候选

2026-11-15。仅原生数据源试验包、具有可用 FLAC SEEKTABLE 和范围读取接口的曲目采用此路径。没有安装为日常版本；一次实机曲尾跳转声音验证见下文，不能替代所有发布门槛。

## 改动

以前虽然仅解码播放附近区间，仍先建立整首 AudioBuffer，内存按歌曲时长增长。本候选用 `windows/pcm-cache.js` 保存已解码区间，每个资源最多 32 MiB、512 个区块。歌曲总长度只作为元数据保留，不据此分配整曲 PCM。全局预算仍预留整个容量，并额外为已预约的不可变声音副本预留 8 MiB；范围解码临时内存继续单独预留 8 MiB。容量预留不等于实际已分配内存，诊断分别报告。

区块淘汰后，从其位置播放需要重新读取编码数据并解码。读取顺序仍是已有编码区间/原生有效缓存/原生缺口取数，没有改成 Web 另行下载。跨区块复制严格检查完整覆盖，缺口抛错并进入既有准备或恢复流程，不把空洞当静音。后台整首磁盘补齐不需要把整首 PCM 留在内存。

播放仍提前创建独立 AudioBufferSourceNode，每个节点持有复制好的采样，淘汰缓存不会修改已预约声音。流式状态始终保留，不能因为曾经遍历整首就误把稀疏缓存传给完整 AudioBuffer 输出路径。频谱读取改为支持按采样位置访问，原有普通 AudioBuffer 分支和 Mac 数据路径保持原实现。

## 检查证据

- 临时内存检查使用一小时长度的元数据和 4 KiB 容量：跨块复制一致，重复填充后的实际容量未超限，淘汰后的区间读取被拒绝，回到旧位置重新填充可读，之前复制出的声音数据保持不变。
- 使用一首完整原生缓存的只读备份，先 XOR 还原并校验授权 MD5。将实际 FLAC 按 0 → 100 → 200 → 10 → 220 秒顺序范围解码，并使用 4 MiB PCM 上限强制发生淘汰。五处各一秒双声道，共 441000 个采样，与同一解码器完整解码后按既有规则转换的 float32 逐样本完全相等。最大实际 PCM 3538944 字节，临时预留全部释放。
- 第一次检查脚本把可选 errors 字段误当必填，修正脚本后完成上述比对；这不是解码器错误。此比对验证区间解码及存储未改变 PCM，不证明与原生/DAC bit-perfect。
- 修改文件语法及试验 ZIP 打包通过。没有写入歌曲缓存或新增常驻测试。

## 仍需验证

实机长时间播放、弱网首次边界、快速跳转及最高支持采样率下的 CPU/内存峰值仍需扩大覆盖。32 MiB 限制只约束本存储；浏览器、原生缓存、解码器内部和声卡驱动的总内存不能由该数值推断。非原生数据源、无索引格式及 Mac 仍可能使用整曲 AudioBuffer，不把 Windows 候选说成跨平台已完成。

## 普通启动后的声音和开关复核

基于 `87bc61b`，增加两项只读诊断字段：音频输出时钟的边界墙钟时间、分块 PCM 实际字节及容量。正式加载的 main.js 与安装包内容哈希一致。使用正常退出和普通启动，没有开启调试端口。

在“我喜欢的音乐”中从 Baptized In Fear 拖到 225.04 秒，目标准备日志约 70 ms，随后自然进入 Open Hearts，宿主接认约 181.9 ms。55 秒 WASAPI 回录完整覆盖边界，无采集错误。与同源参考 PCM 对齐，四个窗口相关性约 0.950/0.939/0.949/0.976，时间误差跨度 1.3125 ms；对齐后边界前后 100 ms 内最长近零连续段为 0 ms。没有观察到该边界的欠载或异常回退。数据见[回录分析](verification/windows-bounded-pcm-audio.json)，原始录音和参考音乐留在本机、不入库。这是一次已有磁盘缓存的曲尾跳转样本，不是冷网络或 DAC 采样精确证明。

播放 Open Hearts 时关闭开关，日志 restore → restored，恢复位置 62.4344 秒，约 254 ms；界面显示原生播放。重新开启后明确显示“当前保持原生播放，下次选歌生效”，没有重现此前 native-only-cache-provider 错误。再次选曲可进入分块 Web 输出。右上角入口、开关和原生关闭按钮位置保持独立。

再次选曲后，监测连续播放 110 秒。解码目标推进至约 108 秒，最近日志中的单资源 PCM 从较低值增长到 33169408 字节后保持在 33554432 字节上限内；没有观察到 stream-output-fallback。随后跳回 5.104 秒，产生重新准备记录，约 50 ms 后继续播放，并重新预约下一首。数据见[容量观测](verification/windows-bounded-pcm-growth.json)：maxPCMBytes 是每次读取最近日志中单资源值的最大值，不是播放器所有资源或进程总内存；最初几行可能包含此前播放的另一首歌。

试验包 SHA-256 为 `42888282fc2da57fb39cc35435b9d5d391a4f5948421e78af4d50aca222f086e`。本轮结束后正常退出并恢复原稳定包，恢复 SHA-256 为 `5f4f30fdc699d055e4c0d7530aba86f79ba92a1e5398d33c2381163f5070c797`，与备份一致；普通启动、保持暂停，关闭行为恢复为最小化到托盘，截图会话已重置。没有清除用户歌曲缓存。
