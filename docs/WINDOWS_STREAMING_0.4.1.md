# Windows 0.4.1：已解码候选提前完成排程

用户反馈“我喜欢的音乐”中 Baptized In Fear→Open Hearts 顿一下。开关、播放模式与音效保护项正常；本次复现两首都命中完整网易云缓存并通过 MD5。

## 改动

0.4.0 的分段调度器即使已完成整曲解码，仍等到剩余音频起点进入两秒窗口才排程。现在完整 PCM 就绪后立即把剩余部分按原定时刻排好，关闭该轨轮询；已预约第一段不重启，不改音质、样式、音源和缓存优先级。记录 stream-fully-scheduled 便于确认提前量。

关键回退、预约和接认事件会写入 C:\betterncm\gapless-windows.log，最多保留近期 80 项指定字段，未知错误文本替换成 unavailable。没有账号、签名 URL、缓存路径或音频内容；不增加菜单项。

## 验证与边界

- 首次尝试自然播放复现过程中用户进行了暂停/继续及 Seek，用户随后明确要求直接拖到曲尾测试。因此不把这次录制称为完整自然播放验收。
- 0.4.1 下一首剩余 PCM 实测提前 226.236 秒排程；旧实现同样状态需等到约 2 秒窗口。
- 按用户要求 Seek 到前曲最后两秒，Baptized In Fear→Open Hearts 预约间隔 0 帧，宿主接认约 183.8 ms，无插件回退。
- 本次 WASAPI 回录回调错误为 0，对齐后的边界 ±100 ms 无近零段，前后位置匹配误差跨度约 1.875 ms。只是一例系统输出证据，不代表模拟设备逐样本无缝。
- 此次未复现明确的音频断口，不能确认延迟排程就是用户原先顿感的唯一原因。保留精简日志供再次发生时诊断。
- 修改文件语法/ZIP 检查通过；不改 Mac 播放逻辑。
