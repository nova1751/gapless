# 持续 Web Audio 接管：0.2.2 候选

目标：解决反复原生/Web交接的延迟，尽量保留原音源规格。0.2.1增加采样率保护，0.2.2补回原有频谱动画输入，见[音质检查](AUDIO_QUALITY_0.2.1.md)和[动态效果修复](VISUAL_PCM_0.2.2.md)。历史跨曲、歌词、恢复及系统控制证据主要来自0.2.0；新频谱、Seek、暂停、跨曲与原生PCM交还另有0.2.2实机记录，不能据此宣布全部原生特性等价。

## 已实现

- 删除曲尾十秒接管、下一首十秒后交还的定时流程，以及普通暂停/Seek触发的交还。
- 普通曲目 Load直接进入 Web，播放、暂停、拖进度、前后切歌均使用网易云原有控制入口。已暂停的原生曲目继续播放时可直接从保存位置进入 Web；已有原生音乐正在响时仍需首次接管。
- 同采样率曲目在同一 AudioContext 连续预约 A→B→C；混合采样率不预约到旧时钟，在正常End/Load边界停止旧节点后重建输出，不为十秒交还重新装载原生音频。
- 后台音源使用实测客户端原有源选择函数，保留授权、音质、缓存及下载偏好。0.1.12 的直接 URL API预加载可能与客户端的缓存选择不同，0.2.0 已改为原有选择器；实查 Moth To A Flame 的源 MD5、28,631,824字节均与客户端选择一致。
- 原生 Load与预加载在途任务的源身份不符时重新取得实际授权源；不会把旧任务结果直接作为当前 Load的音源。
- 独立OfflineAudioContext按源采样率解码，输出上下文采样率必须与解码缓冲及源规格相同。0.2.0允许不同采样率缓冲进入同一输出上下文；0.2.1取消此行为，避免插件级跨率重采样。设备/系统仍可能重采样，不能承诺原生比特等价。
- 不增加CSS、歌词布局、EQ、混音、静音裁剪；歌词内容和高亮继续由原有组件消费播放协议更新。
- 0.2.2按原有音频数据订阅需求，只读当前Web缓冲生成可视化PCM并交给原渲染器；没有第二条音乐输出。暂停、隐藏页面、未订阅及原生恢复时停止采样，旧原生PCM不能覆盖当前Web频谱。
- 关闭开关和异常恢复保留原生恢复路径、音量恢复及页面恢复事务。
- 原生恢复成功清除旧的重新选曲标记；再次进入Web时通过资源管线重新取得可能已被释放的缓存引用，并清除阻塞标记，保持内存预算和下一首预约有效。
- 内部原生恢复的Load只供原生等待者确认，不再重新触发SDK的自动播放；真正的队列重新选曲仍完成原有SDK流程。原生恢复期间用户控制更新最新意图。

系统回跳不是靠增加周期纠偏或再次启动原生音乐解决。历史原生对照也有回跳；持续Web路径仍同时存在原生系统处理器和Chromium发布者，JS接口不能可靠注销前者。释放原生音频实例的短时实机对照仍失败，未把该尝试加入正式播放流程。后续需要唯一系统状态发布者及原生远程命令所有权协调，并重新实测。

完整功能等价尚未完成。0.2.2是开发候选，不是稳定验收结论。Windows仍无运行包，移植应复用控制代次、资源管线、采样率保护及只读可视化采样器，另外验证原生协议与系统所有权。

## 本次回跳反馈后的核对

释放停住的原生音频实例后，用户仍确认回跳；该尝试未加入正式流程。只读反汇编确认系统 Seek 处理器直接调用原生 `setCurrentTime:`，其后延迟更新系统信息；`reloadNowPlayingCenter` 从原生 `currentTime/currentStatus` 读取数据。这条路径不会经过 JS 音乐命令包装。它是可能的覆盖来源，尚不能据此认定每次回跳都来自它。

实际用户点击后再次采样，捕获三次系统Seek。前两次系统收到停住原生后端的时长242.52秒及播放率0，随后约547/545毫秒恢复为Web当前曲时长234.923877秒及播放率1。Web立即发布目标位置，节点按同一渲染边界替换，期间没有Web暂停事件。第三次接近位置的Seek未观察到相同覆盖。这是第二个状态发布者的实机证据，能解释按钮闪动；不是每一次可视进度回跳或所有设备的完整证明，历史原生对照也有回跳。

Chromium注销命令只移除自己的target，不会移除网易云target；BetterNCM-mac明确忽略native_plugin且没有注册的原生插件API。已查的旧播放器接口没有提供系统发布/远程命令所有权：removeAll清理迷你窗列表，stop还会重置原生窗口信息，不能作为无副作用的注销接口。现有JS层无法拦住这条直接原生Seek/NowPlaying路径；需要宿主提供进程内的原生所有权桥，详见[系统所有权要求](SYSTEM_MEDIA_OWNERSHIP.md)。

候选已重新安装并核对源文件。实机确认：暂停原生恢复不丢位置；再次Web继续取得当前/下一首缓存并计入198,485,280字节预算，下一首预约有效；原生窗口播放/暂停按钮与Web状态一致。进一步检查发现内部恢复Load会触发自动播放，已隔离该通知；最新包的快速播放→暂停、等待真实手势失败回退仍保持同一位置和暂停，未出现自动继续。窗口恢复可读后已完成真实点击与最新普通恢复复验：Web播放→暂停Seek→原生恢复仍暂停于240.98秒→再次Web继续且下一首预约有效，最后保持初始暂停位置。记录见[最新恢复复验](verification/mac-web-recovery-0.2.0.json)。随机和完整特性仍未全量验收。
