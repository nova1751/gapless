# 播放接管范围与已知风险

2026-11-14。适用于当前 Mac 0.1.12 和 [Windows 实施方案 v10](WINDOWS_GAPLESS_IMPLEMENTATION.md)。

## 当前推荐

在“只增加无缝衔接，其他行为尽量保持网易云原生”的要求下，保留短时 Web Audio 桥接：原生播放 A，曲尾约 10 秒进入 Web，预约衔接 B，B 开头约 10 秒后经对齐交还原生。时间只是窗口，不能按固定倒计时盲切。

这是按当前需求控制影响范围的工程取舍，不是所有播放器的通用最优方案，也不代表零副作用。若 Windows 有实际可调用、可验证的原生连续播放能力，应优先使用；没有该能力时，按同一临时桥接方案实现并独立验收。

全程 Web 可以减少每曲双向交接，但会让整个播放过程长期依赖适配器。当前没有完成全程 Web 的实现与兼容验收；本次没有扩大播放接管范围，也没有新增全程模式开关。

## 已观察到的情况与未验证项

| 项目 | 当前结论 | 证据与边界 |
|---|---|---|
| 系统播放图标 | macOS 控制中心仍可能短暂切换播放/暂停图标 | 原生内部状态与 Chromium 媒体状态竞争，尚未建立可验证的唯一发布者 |
| 系统进度回跳 | 仍可能新位置→旧位置→新位置 | 关闭插件的原生对照也发生过，不能全归因于插件 |
| 双向声音交接 | 0.1.12 显著压低旧版长叠音与约 22 ms 静音 | 最终应用回录位置变化约 +4.81 / -3.77 ms；另一轮交还有约 0.71 ms 近零片段，非所有设备误差上限 |
| 后台开销 | 增加缓存读取、解码、内存和必要的音频下载 | 完整原生缓存优先；512 MiB 是插件管理预算，不是整个进程峰值保证 |
| 不兼容与故障 | 保持或恢复原生，该次衔接可能有间隔 | 不降低音源档位、不关闭用户音效来强行满足桥接条件 |
| 歌词与其他原生功能 | 需要复用并同步原有协议，不能仅保留外观就认为行为一致 | 当前有取词与进度适配；尚未穷举全部歌词模式、设备和生命周期组合 |

当前输出与控制记录见 [0.1.12 检查](OUTPUT_HANDOFF_0.1.12.md)；系统发布竞争和原生对照见 [系统控制检查](SYSTEM_SYNC_0.1.8.md)。应用回录不覆盖 DAC、蓝牙链和声学输出，不能据此宣布所有设备听感完全无变化。

## 音源质量与输出链

继续使用网易云决定的同一授权音源、请求档位和实际档位；完整缓存还要匹配内容身份。没有新增固定低码率兜底、EQ、交叉淡化或静音裁剪。

这只说明音源选择没有主动降级，不证明两个引擎的最终输出比特相同。Web Audio 暴露浮点 PCM，采样率不匹配时需要重采样；浮点 PCM 本身不是有损压缩，是否存在可听差异仍需针对实际输出比较。[Web Audio PCM 与重采样规范](https://www.w3.org/TR/2021/REC-webaudio-20210617/#AudioBuffer)

当前桥接对已开启音效、音量均衡、空间音频、非 1 倍速等情况保留原生。全程 Web 若无法沿用这些功能，也必须明确回退；不能把原生设置仍显示“开启”当作功能已实际生效。

## 歌词为什么仍需适配

音频引擎负责出声，网易云的取词和原有渲染逻辑可以继续复用；歌词滚动/高亮则需要正确的当前曲目、时长、进度、暂停及 Seek 状态。

当前 [Mac 适配代码](../mac/player.js) 通过 `answerLoad` 接认当前曲目，在原有字段就绪后由 `refreshLyrics` 调用网易云取词流程；`progress` 回报 Web 的播放时钟，拦住停住的原生后端旧通知。它们是明确需要维护的兼容逻辑，不等于所有歌词功能已经完整验收。Windows 必须查明自己的数据流，不直接复制 Mac action 名称或模块编号。

全程 Web 不需要重写整个客户端，但必须覆盖所有受后端替换影响的控制、歌词同步、系统媒体状态、统计和恢复语义。任何漏通知、乱序或旧代次回写都会影响原界面；长期接管把这些风险从桥接窗口扩大到整段播放。

## 全程 Web 的后续准入条件

全程模式仅是后续可选路线，不能作为当前已交付功能。进入开发与发布前至少明确：

- 一个权威的播放状态与命令路由，避免原生旧进度/暂停覆盖 Web 真实状态。
- 当前/下一首有限预取、连续队列接认、手动切歌及不同规格资源的处理，不扩大为整列表解码。
- 歌词、窗口和系统 Seek、暂停/继续、音量、收听累计等原有行为的逐项兼容。
- 长时间播放、休眠、设备切换、刷新、授权/缓存/解码失败，以及关闭模式后的原生恢复。
- 指定版本和设备的实际声音、资源与 UI 验收；未确认的原生功能明确回退。

这些工作会明显增加实现与验证范围。当前推荐与提交仍是短时桥接；Windows 不复制 Mac 已知图标闪动，不把 Mac 的延迟校准或日志当作 Windows 已验证结果。
