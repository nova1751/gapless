# macOS 无缝播放 0.3.20

源码、交付包、安装及实际页面均为 **0.3.20**。已同步最新 main 的延迟／预读优化，补回文件版本检查、未知 Mac 版本回退、停止失败及旧加载清理保护。实际 3.1.12 缓存 MD5 与同曲恢复通过；保留原音质设置和样式。宿主 0.1.7、管理入口 1.2.1。[本轮记录](../docs/MAIN_REVIEW_0.3.20_0.4.33.md)、[版本与哈希](../docs/versions.json)。

## 本次更新

0.3.20 保留 0.3.19 的预读、解码器复用、暖缓存和并行预热，补充缓存版本、期限及代次保护；停止未确认的辅助通道不自动重开，未知 Mac 版本只保留管理入口。共用 Range 接收恢复有界长度检查，不修改音频样本。

0.3.19 同步 Windows 0.4.23–0.4.31 的稳定性与低延迟优化并修复 Mac 端既有缺陷：启用 `indexedReadAheadSeconds: 16` 与 `scheduleAheadSeconds: 10`（含 6 MiB 字节上限、2 秒块、`onended` 续喂、`farFuture` 仅预读 4 秒及完成态全量排程）解决播进 4 秒误取消在途补缓冲及远期下一首抢通道超时问题；`progress()` 与 `MacMediaSession` 在 Seek 期间抑制旧位置上报，消除进度条及控制中心回跳；无缓存切歌时立刻上报 `PlayProgress(0, cache=0)` 与 `Buffering`；磁盘已有覆盖时起播/拖动门槛降至 0.5 秒并用事件唤醒替代 25 ms 轮询，未缓存拉数采用自适应窗口（高优 `1200 / 1800 / 2500 ms`、后台 `1800 / 2400 / 2800 ms`，8 秒截止前 400 ms 封顶）并在停止后短时复核索引提交；`prefetch()` 在播放态等待当前曲 ≥6 秒缓冲后再拉下一首（暂停态仍允许预加载）；`loadOwned` 并行预热 `AudioContext` 与门控/缓冲并具备 `openSerial` 并发取消与异常清理，暖缓存扩至最多 4 首 LRU（≤160 MiB）；修复 `mounts` 无上限增长、缓存有效根目录记忆、对已定稿完整 `.uc!` 跳过每次读前后多余的 `getProperties` IPC；为 Webpack 模块查找增加带 `try/catch` 的特征签名回退并放宽固定 `3.1.12` 版本硬锁（保留全部运行时接口校验）；支持重新开启开关时重置空闲 `nativeSource.fault`。未在 Mac 实机验收，不修改授权音源、解码样本、音量曲线或采样率策略。

0.3.14 对索引暂时不可读、有效路径消失及文件流断开增加一次有界重查，重新验证原生索引和有效区间，保留原有 8 秒期限；正常读取不增加等待。持续失败仍原生回退，用户取消与超时分开记录，`nativeCacheSource.refreshes` 记录重查次数。没有修改授权音源、解码样本、音量、采样率或输出时钟，也不新增永久缓存。

以下是此前版本的改动与历史验收范围：

0.3.13 同步最新 main 的原生队列与缓存原则：心动模式调用已核对的网易云选曲函数，只预约已经确定的相邻项；实际相邻源不变时，重新编号不撤销预约。MD5 按约 4 ms 工作预算通过 MessageChannel 让出，保留完整校验；缓存索引走宿主已有的有界异步文件通道，避免同步文本读取阻塞整个宿主。用户目录从已有宿主元数据识别，不枚举桌面／文稿／音乐目录。

启动只检查实际播放接口，不依赖歌词页先初始化；没有更新的实例或控制时保留延迟恢复快照，新的播放或 Seek 优先。原生恢复失败时，下次恢复保留未完成的目标位置；暂停选曲失败后用原有暂停恢复流程清理加载任务，新的控制优先。实际接口确认原曲 218.156635 秒、暂停；宿主 API 已恢复响应，但真实音乐缓存本轮仍返回读取失败。队列、校验和快照为隔离验证，不能当作本轮真实无缝听测。

0.3.12 修正缓存读取失败回退原生后，网易云仍停在「首次加载中」、进度条显示 00:00 的问题。有待完成的原始 SDK Load 时复用其授权资料和加载回调，不嵌套调用 SDK Play 覆盖订阅；恢复原生后完成原始 Load，让客户端自行清理加载状态。缓存错误不再强制重新选曲。实际故障注入后原生与界面进度继续推进；宿主缓存服务恢复、页面重载、暂停位置恢复已完成。

0.3.11 修正正常从头播放也可能在曲尾附近出现的 FLAC 分块解析短结果：用有界下一帧前瞻和流式解码确定边界，采样数与格式仍须完全匹配，检查内置解码器真实错误数组，并保留区间失败原因。123 个原生缓存索引区间通过，原问题段 PCM 与连续解码逐采样一致。该修正已包含在当前完整 0.3.20 页面，数值证据保留原版本。

0.3.10 修正无关队列更新也撤销预约的问题：实际下一首、源规格、输出时钟及边界仍匹配时保留预约；接认阶段从原曲重新计算下一首，确认同一队列项后保留接认。真正的选曲、账号／档位／源变化、输出或缓存故障仍有原生回退。`gaplessMac.status().lastFallback` 保留本次页面最近一次切回原生的原因、位置和源采样率。[修正范围与 Windows 建议](../docs/QUEUE_BOUNDARY_0.3.10.md)。

## 安装与回退

```sh
python3 mac/package.py
python3 mac/install-menu.py
```

1. 生成 `dist/gapless-player-mac-0.3.20.plugin`，交付副本见 [0.3.20 包](../releases/gapless-player-mac-0.3.20.plugin)。复制到 `~/Library/Application Support/BetterNCM-mac/plugins/`；同 slug 只留一个活动版本，旧包移到目录之外。本机已保留旧包用于回退。
2. 菜单安装脚本只写 `/Applications/BetterNCM.app/Contents/Resources/app/src/prelude/gapless-plugin-menu.js`，不改宿主原文件，不修改 CSP。`--market` 仅将指定 profile 的 `mac.pluginManager` 保存为 `true`，复用已内置的 PluginMarket，其他配置不变；不加该参数仅更新菜单，保留市场原有设置。宿主 API／自动发现接口不匹配时退出，保留原菜单。非默认安装位置可加 `--app /path/to/BetterNCM.app`；自定义 profile 加 `--profile /path/to/profile`。
3. 由宿主重载插件并刷新页面，或正常退出后重新打开。核对菜单安装版本、`gaplessMac.version` 和 [当前状态](../docs/CURRENT_STATUS.md)。初次真实输入之前 Web Audio 可以等待授权，不主动发声。

移除菜单扩展：`python3 mac/install-menu.py --remove`，下次重载恢复宿主原菜单；已保存的市场启用设置保留，无缝播放包与其独立。播放器回退可关闭无缝开关，或正常退出后换回插件目录之外的旧包。本机已保留旧包。宿主升级可能移除独立 prelude；升级后需重新检查接口并安装。

宿主原管理页标题的 **1.3.4** 是模拟的 BetterNCM 兼容接口版本；新增说明显示实际 Mac 宿主 **0.1.7**。无缝插件、菜单和宿主分别版本化，市场中的第三方插件另有各自版本。

## 播放与缓存

同源、同档位内存 → 原生有效磁盘区间／原生解析器返回的明文本地 FLAC → 原生串行 Load → Seek → Stop 准备缺口、提交缓存。辅助实例不 Play，通知不覆盖主曲目、歌词、进度或系统状态。插件只读有效数据并解码，不写 UC／IDX，不建立第二套永久音乐缓存。

编码区块共享 64 MiB，索引路径每首 PCM 32 MiB，其他路径受 512 MiB 管理预算约束。当前曲、用户 Seek 优先；当前 PCM 余量足够后才后台补齐，任务有期限并可取消，不保证退出前整首落盘。同采样率预约连续输出，异率重建上下文可能有短间隔。

无缝开关优先，Web 输出期间不执行冲突的原生音效，保存值供关闭后原生使用。关闭恢复原生并释放工作缓存，重新开启可准备当前曲。系统控制中心进度回跳仍有原生对照问题，不能宣称完全解决。
